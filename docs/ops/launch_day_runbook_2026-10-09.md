# 출시 운영 한 장 — 문제 등급표 · 되돌리기 연습 · 시간별 점검표 (게임성 개발 3, 2026-10-09)

시스템 점검 1회차 더하기 8번(`docs/design/system_review_round1_2026-10-09.md`). 이미 있는 도구만 써요: 스위치판(`docs/ops/switchboard_2026-10-09.md`), 서버 오류 기록, 건강 보고(`docs/design/health_report_server_2026-10-09.md`), 환경별 저장소(`docs/design/ops_safety_server_2026-10-09.md`). **게시·'모든 서버 종료'는 사용자가 누르고**, 아래 줄은 누르기 전에 무엇을 볼지 정해 둔 거예요.

## 0. 읽는 곳 세 군데 (Studio에서 게임 장소를 연 상태, Play 중 명령창)
`PLAYER`는 Play 중인 내 계정 이름이에요(메인 Studio에서는 "Player1"이 아님).
```lua
-- 서버 오류 (진짜 게임의 최근 50개)
print(game.ServerScriptService.DebugCommand:Invoke(PLAYER, "Errors", "live"))
-- 건강 보고 (진짜 게임의 최근 24시간; "live:6" = 6시간)
print(game.ServerScriptService.DebugCommand:Invoke(PLAYER, "Health", "live"))
```
스위치판 읽기·쓰기는 `docs/ops/switchboard_2026-10-09.md`의 줄(복사해 붙이기). 분석 이벤트(퍼널·PromptNearKO·폰 프레임 PerfFps/PerfFpsLow/PerfMem)는 Creator Hub 분석 화면.

## 1. 문제 등급표 — 먼저 등급을 정하고, 그 줄의 첫 행동만 한다
| 등급 | 뜻 | 예 | 첫 행동 (10분 안) |
|---|---|---|---|
| **S0** | 돈·저장이 틀어짐 | 골드·아이템이 복사되거나 사라짐, 산 패스를 못 받음/값이 이상함, 저장이 안 됨·되돌아감 | ① 스위치 `PassSales`를 끈다(패스 관련이면) ② 퍼진다 싶으면 관련 스위치(`Halloween`/`CrownWar`/`Goose`)도 끈다 ③ 원인이 안 잡히면 **되돌리기(§2)** — 사용자가 판단 ④ `Errors live`·`Health live`를 남겨 둔다 |
| **S1** | 못 들어오거나 계속 튕김, 첫 10분 진행이 막힘 | 접속 직후 멈춤, `Errors`에 같은 오류가 계속, 대장간/초원 단계에서 못 넘어감 | ① `Errors live`로 어느 스크립트인지 ② 그 기능에 스위치가 있으면 끈다 ③ 없으면 **되돌리기(§2)** |
| **S2** | 한 기능만 깨짐, 진행은 됨 | 왕관전 점수·거위·랭킹·Halloween 한 곳, 사운드/화면 한 부분 | 스위치로 끄거나 그대로 두고 다음 수요일 업데이트에 고침 |
| **S3** | 보기에만 틀림 | 글자·그림·소리·위치 | 목록에 적어 수요일 업데이트에 모음 |
- 등급이 둘 사이면 **높은 쪽**으로 한다. 돈·저장은 늘 S0.
- 스위치로 끌 수 있는 것은 네 가지뿐이에요(`PassSales`, `Halloween`, `CrownWar`, `Goose`). 나머지는 게시가 필요해요.

## 2. 되돌리기 연습 — 게시하기 **전에 Beta 장소에서 한 번** (목표 15분 안)
연습의 목적은 "화면 이름과 걸리는 시간을 한 번 적어 두는 것"이에요(Roblox 화면 이름은 바뀔 수 있어서 연습 때 실제 이름을 아래 칸에 적어요).
1. 지금 판을 적는다: 게임 설정 맨 아래 글자 `beta-prep … · place v<번호> · server …`(= `Config.BuildLabel` + 장소 버전). 번호: ______
2. Creator Hub의 그 장소 **버전 기록**에서 직전 판을 골라 되돌린다(또는 직전 파일을 다시 게시). 누른 화면 이름: ______ , 걸린 시간: ______
3. **모든 서버 종료**(Creator Dashboard → 체험 → 서버). 새 서버가 열릴 때까지: ______
4. 새로 들어가 설정 맨 아래의 `place v<번호>`가 직전 판인지 본다.
5. **저장이 살아 있는지:** 되돌리기 전에 테스트 계정으로 출석·펫·일기 같은 새 필드가 있는 저장을 만든다 → 옛 판으로 들어갔다 나온다 → 다시 새 판으로 들어와 그 필드가 남아 있는지 본다. (남지 않으면 S0 되돌리기는 저장 손실 위험이 있으니 **스위치로 끄는 길을 먼저** 쓰고, 이 결과를 검수에게.)
6. 연습 결과(번호·화면 이름·시간·5번 결과)를 이 파일 §2에 적고 push.
- 되돌리기 뒤에는 `Config.Env.Names`가 맞게 들어 있는지(장소 id), 스위치판 문서가 안 바뀌었는지 본다(스위치는 저장소에 있어서 되돌리기와 무관).

## 3. 시간별 점검표 — 출시 시각 T (예: 10/31 11:00 KST 베타)
각 줄: **본다 → 정상 모양 → 이상하면 §1 등급.** 한 번에 한 줄만, 해결 못 해도 시간표는 계속 돌린다.
| 시각 | 본다 | 정상 모양 |
|---|---|---|
| T-60분 | 스위치판 읽기 / `Errors live` / `Health live` | 스위치 모두 true(또는 문서 비어 있음), 오류 없음 또는 알려진 것만, 건강 보고 데이터 없음(출시 전) |
| T-10분 | `Config.Env.Names`에 이 장소 id가 `Beta`(또는 `Live`)로 있는지, 설정 맨 아래 `place v` | 맞는 번호, 저장소 이름 끝에 `_Beta`/`_Live` |
| T+0~10분 | 새 계정으로 직접 입장: 진영 → 직업 → 대장간 걷기 → 첫 무기 → 초원 | 막힘 없이 5분 안에 슬라임 5까지, `Errors live`에 새 줄 없음 |
| T+30분 | `Health live:1`, `Errors live` | 접속 수·플레이어-시간이 0이 아님, 띠별 XP/골드 per 플레이어-시간이 숫자로 나옴, `Alerts: none` |
| T+1시간 | `Health live:2` + 분석(온보딩 퍼널, `PromptNearKO` = **0이어야 함**, `PerfFps` 폰 평균) | 퍼널 첫 두 단계가 비어 있지 않음, PromptNearKO 0, 폰 평균 FPS가 급격히 낮지 않음 |
| T+3시간 | `Health live:6` | `QUIET`/`SURGE`/`GOOSE` 경보 없음. 있으면 아래 §4 |
| T+6시간 | `Errors live`, 분석 `ServerError` 이벤트 | 같은 오류가 반복되지 않음 |
| T+24시간(D1) | `Health live:24`, 분석 퍼널 | 가장 큰 낙차 한 곳을 적어 둔다(고치는 건 11/03 판단, `retention_round`) |
- 이상이 나오면 "무엇을 봤는지 + 등급 + 한 일"을 한 줄로 §5에 적는다.

## 4. 경보가 뜨면 (`Health`의 Alerts 줄)
- **QUIET** (3시간 동안 아무 서버도 안 씀): 게임이 열려 있는지(접속 가능?), 새벽이면 정상일 수 있음. 열려 있는데 데이터가 안 쌓이면 `Errors live`와 DataStore 쓰기 실패 경고(`save H…`)를 본다 — S1 후보.
- **SURGE** (띠별 XP 또는 골드가 앞 시간의 2배 이상): 한 곳(예: `GoldIn`의 한 출처)이 갑자기 큰지 `Health` 줄에서 찾는다. 사람이 몰린 것(플레이어-시간도 같이 늚)이면 정상, 플레이어-시간은 그대로인데 늘었으면 **돈 문제 후보(S0)** — 그 출처를 잠그려면 게시가 필요하니, 먼저 `PassSales`가 관련이면 끈다.
- **GOOSE** (한쪽이 75% 이상 이김): 공정성 문제 후보(S2). 거위 보상 숫자는 `Goose` 줄의 평균 보상으로 본다. 급하면 `Goose` 스위치를 끈다.
