이 PC에서 Codex 채팅과 별개 프로세스로 실행한다. 클로드 API 키는 프로젝트의 git 제외 `.env`에 있는 `ANTHROPIC_API_KEY`만 메모리에서 읽는다. 키는 요청 본문·결과·로그에 쓰지 않는다.

## 실행과 중지

저장소 루트에서:

```powershell
py tools/claude_doc_worker.py start
py tools/claude_doc_worker.py status
py tools/claude_doc_worker.py stop
```

- `start`: 숨겨진 독립 프로세스로 시작하거나 중지한 작업을 이어서 실행한다. PC가 꺼지면 멈춘다.
- `status`: 프로세스 생존 여부와 묶음별 단계를 보여 준다.
- `stop`: 중지 표시를 남긴다. API 응답 수신 또는 통신 시간 초과 뒤 멈춘다. 이미 요청한 API 비용이 취소된다는 뜻은 아니다.
- 프로그램이 다시 실행돼도 완료된 API 결과를 재사용한다. 오류가 난 묶음은 자동으로 유료 재시도하지 않고 확인 필요 상태로 남긴다.

## 이번 작업

중단 작업의 `build/md_resume_2026-10-09/inventory.json`을 사용한다. 원래 303개 문서 7묶음과 새 `docs/handoff/README.md` 1개가 대상이다. 이 목록과 작업 사본은 `build/claude_doc_worker/`에 고정 저장한다. 기존 수정본도 보존한다.

1. Sonnet 5.5가 수정안을 만든다.
2. 정확히 한 곳에 대응하는 수정만 별도 `candidate/` 복사본에 반영한다.
3. 별도 요청의 Opus 5.5가 수정본과 원래 변경 내역을 반박 검토한다.
4. 반박 수정안이 있으면 복사본에 반영하고 한 번 더 검토한다. 묶음당 수정 검사 1회·반박 검사 최대 2회이며, 미해결 항목은 통과로 표시하지 않는다.

결과 파일:

- `build/claude_doc_worker/진행상황.md`: 묶음별 진행.
- `build/claude_doc_worker/candidate/`: 검토용 수정 문서.
- `build/claude_doc_worker/changes.patch`: 시작 때 복사한 문서와 수정본의 차이.
- `fix_group*.json`, `review*_group*.json`: 수정 근거·반박 결과·미해결 항목·AGENTS 수정 제안.
- `*_usage.json`: API 응답에서 받은 토큰 사용량. 실제 요금·잔액 확인은 Claude Console 기준.

프로젝트 원문·AGENTS.md·코드·Studio·Git은 자동으로 바꾸지 않는다. 실제 반영 전에 반박 결과와 시작 이후 원문 변경 여부를 확인한다. API 작업 종료와 프로젝트 반영 완료는 구분한다.
