# 스킬 습득·장착과 전직 방향 — 2026-10-04

> 기록용(2026-10-09 검수): 2026-10-04 기록이다. 지금은 수동 + 자동 전투 켜기/끄기(SPEC A23-1, 자동 해금은 첫 스킬 뒤 A23-71), 직업마다 스킬 3개를 Lv5·15·25에 저절로 배우는 설계(NPC·골드 없음, A23-49·A23-71; 2·3번째 스킬은 아직 `Config.Skills.ZEnabled`·`XEnabled` 꺼짐, 10/20에 판단 — RELEASE_PLAN), 기본 키 Z·X·C(A23-78)다. 아래 '자동 공격 제거'·'NPC에게 배워 장착'·미구현 서술은 당시 상태다.

이 문서는 최신 사용자 요구와 코드에서 확인한 상태, 남은 검증을 구분한 기록이다. **문서 최신화는 스킬 상점·습득·슬롯 구현이나 Studio 적용 완료가 아니다.** 최신 수동 전투 소스의 통합 검증은 2026-10-06 작업 재개 후 진행한다.

## 1. 최신 사용자 결정

- **게임성을 먼저 진행하고 그림은 나중에 한다.** 이번 초보 무기 9종은 시안으로만 보관하며 승인·업로드·게임 적용으로 처리하지 않는다. 고유 무기별 장비 체계와 중립 전용 장비 기획도 이번 단계에서 보류한다.
- **2026-10-04 사용자가 이전 설계에서 마음을 바꾸어 수동 전투를 선택했다.** 과거 자동 공격·충전 게이지 중심 전투는 폐기한다. 공격 버튼·키를 한 번 누르거나 화면을 짧게 클릭했을 때만 기본 공격한다. 길게 누르기·대기만으로 공격을 반복하지 않는다. 자동 공격 버튼·단축키·서버 반복 공격과 자동 발사에 의존하는 성장 안내도 제거한다.
- **Charge 게이지 자체를 완전히 제거한다.** 충전 선행 조건만 낮추는 변경이 아니다. 충전 링·충전 숫자·PERFECT 표시와 충전에 따른 자동 발사도 제거 대상이다. **MP 소모는 유지한다.** MP와 서버 재사용 대기·전투 자격 검증은 별개다.
- 스킬은 요구 레벨을 만족한 뒤 **배우고, 배운 스킬을 슬롯에 장착해 사용**하는 방향이다. 레벨 도달만으로 모든 스킬을 자동 지급하는 계약이 아니다.
- 기본 스킬은 **실제 NPC 상인과 상호작용해 습득**한다. 희귀한 스킬의 획득 경로는 드롭·어려운 퀘스트·보스 보상으로 구분한다. 구체적인 목록·확률·요구 재료는 미정이다.
- **전직은 후속 단계**다. 이번 문서가 전직 직업이나 분기 이름을 확정하지 않는다.
- 원격 AI 대화는 연결하지 않았다. 현재 NPC 상황 대사와 실제 AI 서비스는 구분한다. 새 유료 API·3D 제작을 승인한 문서가 아니다.

현재 전투 계약은 [GDD §0-2](../GDD.md)와 [SPEC_ADDENDUM A22](../SPEC_ADDENDUM.md)를 따른다. 과거 자동 공격·충전·PERFECT·자동 발사·Lv5 자동 공격 해금 설명은 현재 구현 요구가 아니다. 선악 선택·도움과 경쟁의 결과라는 핵심은 유지한다. `RELEASE_PLAN.md`의 베타 2026-10-31 11:00 KST·정식 2026-12-19 날짜는 변경하지 않는다. **[낡음 2026-10-11: A23-119로 베타 2026-12-01 11:00 KST(장인 길드 포함)·기능 마감 11/24·정식 2027년 1월 말.]** 스킬 확장 전체를 특정 출시 단계에 넣겠다는 일정 약속도 하지 않는다.

## 2. 실제 코드에서 확인한 현재 상태

| 내부 전투 직업 ID | 빛 표시명 | 뿔 표시명 | 중립 표시명 | 현재 기본 공격 | 기존 Release 한 가지의 표현 |

| `Warrior` | 성기사 | 광전사 | 대장장이 | 주변 근접 공격 | 내려찍기·충격파 |
| `Mage` | 빛의 마법사 | 흑마법사 | 연금술사 | 원거리 마법·범위 공격 | 운석 |

- **내부 전투 직업은 3개**다. 진영별 한국어 표시명이 달라도 독립된 9개 전투 직업 시스템이 구현된 것은 아니다. 중립의 대장장이·연금술사·사냥꾼은 현재 이 3개 전투 기반을 공유하며, 이름만으로 제작·연금 기능이 완성됐다고 볼 수 없다.
- 각 직업은 기본 공격 `Swing`과 **기존 특수 공격 `Release` 한 가지**를 갖는다. 전사 충격파·마법사 운석·궁수 화살 비는 현재 표현을 설명한 말이며, 새 승인 스킬 이름을 확정한 것이 아니다.
- 기존 `Release` remote는 선택한 스킬 ID나 슬롯 번호를 받지 않고 현재 직업으로 동작을 결정한다. 기존 효과가 있다고 해서 여러 스킬을 배워 고르는 구조가 있는 것은 아니다.
- 조사 시점 `src/`에 `LearnedSkillIds`, `EquippedSkillSlots`, `AdvancementId`, `LearnSkill`, `EquipSkill`, `UseSkill`, `SkillService`, `SkillMerchant` 구현은 없었다. **학습 데이터·학습 NPC·슬롯 장착·사용 remote는 미구현**이다.
- `ClassService`의 현재 직업 변경은 기본 전투 직업을 바꾸는 기능이다. 무료 변경 시 레벨 초기화 또는 변경권 사용 경로가 있으며, 향후 상위 직업으로 성장하는 **전직과 같은 기능이 아니다.**
- MP는 `VitalsService.TrySpendMana`가 서버에서 검증한다. 현재 기본 스킬은 `Config.BasicSkill`의 **MP 20·재사용 3초**를 사용한다. 성공한 사용만 서버 재사용 시간을 소비하며, 실패한 MP 검사로 재사용 시간을 시작하지 않는다. 현재 수치는 플레이하면서 조정할 수 있으며 새 스킬들의 MP 비용·학습 레벨·가격을 승인한 뜻은 아니다.
- **최신 미커밋 소스에는 수동 전투·Charge 제거가 반영돼 있다.** `CombatService`는 자동 공격·자동 발사 호출을 거절하고 자동 전투 반복 루프를 제거했다. 충전 값과 PERFECT 상태는 호환용 0으로 유지한다. `ClassChosen`과 준비 상태 검증은 직접 `Swing`·원격 `Swing`·예약 수동 공격에 들어 있다.
- `HUD`는 공격 입력당 한 번만 요청하고 충전 링·숫자·자동 공격 버튼과 단축키를 제거했다. 기본 스킬은 MP·남은 재사용 시간을 표시한다. `Fx`의 PERFECT·자동 발사 표시와 “다음 해금” 예고는 제거돼 있다.
- `CameraFollow`는 왼쪽 버튼의 짧은 클릭과 드래그를 분리한다. 6px 이상 이동한 드래그는 카메라 회전으로 처리하고 공격을 보내지 않는다. 기본 공격 요청은 드래그가 아닌 클릭을 놓았을 때 발생한다.
- 위 내용은 **파일을 읽어 확인한 구현 상태**다. 최신 변경 전체의 실제 PlayerScripts 통합·실행 Studio 적용·저장본 동일성, 실제 마우스·터치 체감, DataStore 재접속·다인 플레이는 아직 합격으로 판정하지 않는다. 승인 카드 이미지 안에 남은 게이지 문구도 디자인 보류 상태로 구분한다.

## 3. 기술 계약 제안 — 아직 미구현

### 직업 식별자

표시명·진영·성별을 스킬 소유권 키로 사용하지 않는다. 현재 `Class` 필드와 기존 전투·코스튬 연동을 유지한 채, 향후 필요한 아래 개념을 구분하는 안이다.

| 개념 | 역할 | 현재 연결과 주의점 |
|---|---|---|
| `BaseClassId` | 전사·마법사·궁수의 전투 기반 | 기존 `Warrior`·`Mage`·`Archer`를 안정적인 기준으로 사용 |
| `ClassId` | 현재 선택한 직업 정의의 ID | 전직이 없을 때는 기반 ID와 같게 해석 가능. 현재 `ClassService.GetClass()`가 읽는 값을 한 번에 다른 이름으로 치환하지 않음 |
| `AdvancementId` | 향후 전직 경로 | 미전직은 비어 있음. 전직 명칭·분기·조건은 나중에 결정 |
| `Faction` / `CharacterGender` | 진영과 외형 | 직업의 한국어 이름이나 성별이 바뀌었다는 이유로 학습 목록을 삭제하지 않음 |

같은 의미의 필드 둘을 각각 독립 갱신해 불일치시키지 않는다. 현행 `Class`와 새 식별자의 호환·마이그레이션 경로를 먼저 정한 뒤 도입한다. 중립 표시명을 `Config.Classes`의 새 키로 오인해 현재 공격·무기·코스튬 조회를 깨뜨리지 않는다.

### 저장 데이터와 스킬 정의

- 스킬마다 번역·이름·아이콘 변경과 무관한 **고정 `SkillId`**를 둔다. ID의 예시 형식은 `warrior.basic_release`이며, 실제 이름이나 신규 스킬의 승인이 아니다.
- `LearnedSkillIds`: 서버가 인정한 배운 스킬 ID의 집합을 영속 저장한다. 중복 학습·보상 재수령이 같은 스킬을 반복 구매하게 하지 않는다.
- `EquippedSkillSlots`: 슬롯과 학습된 ID의 연결을 영속 저장한다. 슬롯 수·해금 방식·슬롯별 입력 키는 아직 정하지 않는다. 저장 형식은 중간 빈칸이 사라지는 배열 문제를 피하도록 명시적인 슬롯 키 등으로 확정한다.
- 서버의 스킬 정의에는 허용 전투 직업·필요 시 전직/진영 조건·최소 레벨·획득 경로·MP 비용·재사용 대기·서버 실행 핸들러를 둔다. **학습 레벨·가격·새 스킬 목록·피해량을 여기서 임의로 정하지 않는다.**
- 배운 사실과 지금 사용할 수 있는 자격을 분리한다. 직업 변경·레벨 초기화 후 자격을 잃은 스킬은 사용을 막고 부적합한 슬롯을 해제하되, 배운 기록을 임의로 지우지 않는 안을 우선 검토한다. 전직·환생 시 보존 정책은 실제 구현 전에 확정해야 한다.
- 기본 공격과 기존 `Release` 효과를 재사용할 수 있지만, 학습·장착·발동은 서버가 검증하는 하나의 경로로 모은다. 옛 `Release` remote가 슬롯·소유권 검사를 건너뛰는 뒷문으로 남지 않게 한다.

### 서버 검증

아래 remote 이름은 제안이며 현재 등록됐다는 뜻이 아니다.

| 동작 | 클라이언트가 보내는 최소 의도 | 서버가 다시 확인할 조건 |
|---|---|---|
| `LearnSkill` | 고정 스킬 ID | 준비·생존·직업 선택, 실제 등록된 학습 NPC와의 거리, NPC 판매 목록, 레벨·직업/전직·진영 자격, 이미 배웠는지, 서버 가격·소모 재료·잔액 |
| `EquipSkill` | 슬롯과 배운 스킬 ID 또는 해제 의도 | 슬롯 범위, ID의 유효성·소유권, 현재 레벨·직업/전직 자격, 중복 장착 정책 |
| `UseSkill` | 슬롯 번호 | 살아 있는 현재 캐릭터, 서버 슬롯에 장착된 실제 ID, 소유권·레벨·직업/전직, MP, 스킬별 재사용 대기, 전투 구역·표적·거리·명중 유효성 |

클라이언트가 가격·피해량·쿨다운 만료 시각·습득 성공 여부를 결정하지 않는다. 학습 결제와 소유권 기록 사이에 양보하지 않으며 중복 요청에도 한 번만 소비한다. 서버 전투 조건 확인 후 MP와 재사용 대기를 확정한다. MP 부족·잘못된 표적·사망 등 거절 경로의 자원 소비 여부도 명시하고 검사한다. 슬롯 교체·다른 슬롯으로 옮기기·다중 클릭으로 같은 스킬의 재사용 대기를 초기화하지 않는다.

희귀 스킬은 서버의 처치·퀘스트·보스 보상 지급 경로에서 소유권을 추가한다. 클라이언트의 “보스를 잡았다” 주장으로 지급하지 않는다. 재접속·보상 재시도에도 중복 지급되지 않게 한다. 아직 없는 희귀 스킬·보스를 안내 NPC가 이미 얻을 수 있다고 말하지 않게 한다.

### 기존 계정 이관

- 학습 데이터가 없는 기존 계정에는 **현재 선택한 기본 직업의 기존 기본 스킬 1개를 무료로 연결**하는 안이다. 세 직업의 전체 스킬이나 희귀 스킬을 일괄 지급하는 안이 아니다.
- `ClassChosen=false`인 계정은 저장 기본값이 `Warrior`라는 이유로 먼저 전사 스킬을 확정하지 않고, 실제 첫 직업 선택 뒤 해당 기본 스킬을 연결한다.
- 기존 학습·슬롯 데이터가 유효하게 있으면 덮어쓰지 않는다. 신규 슬롯 데이터가 없을 때만 기본 스킬을 배치하며, 이관을 반복해도 결제·중복 보상이 생기지 않게 한다.
- 미등록 ID·손상된 슬롯·이전 버전 자료는 실행에서 제외하고 별도로 검토한다. 더 높은 데이터 버전을 조용히 덮어쓰지 않는 기존 저장 정책을 유지한다.
- 저장·재접속 검증은 Studio 메모리 모드 통과와 별개다. 실제 DataStore 유지·복구를 확인하기 전 영속 저장 완료로 보고하지 않는다.

## 4. 자동 공격·Charge 제거의 연결 점검

소스에 반영된 전투 변경과 아직 없는 스킬 확장을 구분한다. 아래 반영 상태를 실행 Studio에서 다시 확인해야 한다.

- `CombatService`: 자동 전투·충전·PERFECT 분기는 제거됐고 기본 스킬 피해·범위는 `Config.BasicSkill`을 사용한다. 과거 클라이언트용 자동 공격 원격은 자동 공격을 켜지 못하게 막혀 있다. 실제 실행에서도 대기·위조 요청·직업 미선택으로 공격이 시작되지 않는지 재검증한다.
- `HUD`·`Fx`: 충전 링·충전 숫자·PERFECT 문구·자동 공격 버튼/단축키·자동 발사 전용 표현 제거가 소스에 반영됐다. MP 수치·MP 부족 안내·기본 스킬 사용 결과는 유지한다. 실제 클라이언트에 오래된 UI가 남는지 확인하며, 공격 충격파의 공간 효과와 HUD 충전 링을 혼동하지 않는다.
- 퀘스트: 기존 `Release` 과제의 `MinStacks` 같은 충전 전제와 진행 신호를 재검토한다. 사라진 조건을 요구해 퀘스트가 영구 정지하지 않게 한다.
- 진영 지원: 빛의 아군 충전 공유는 제거됐고 실제 피해에 따른 아군 회복은 유지돼 있다. 실제 전투에서 협동 효과를 재검증한다. 대체 보너스를 승인 없이 새로 만들지 않는다.
- 안내: 현재 문서 계약은 GDD §0-2·SPEC_ADDENDUM A22다. Lv5 자동 공격 해금·자동 공격 키·충전 후 발사를 설명하는 과거 안내가 실제 클라이언트에 남는지 확인한다. 새 슬롯 체계가 생기기 전 “배워서 장착했다”라고 안내하지 않는다. 승인 카드 비트맵에 남은 과거 문구는 추후 디자인 작업으로 처리한다.
