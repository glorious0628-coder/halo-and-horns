# HaloArcherM 얼굴 원본 독립 재검사

`py tools/audit_halo_archer_face_source.py`로 재현한다. 원본 파일 SHA를 시작·종료에 검사하며 Studio·네트워크·업로드·유료 작업은 하지 않는다. `source_audit.json`이 이번 재계산 결과다.

- 원본 Tripo baseColor는 2048×2048, fixed 머리는 1024×1024다. 같은 얼굴 438면의 UV 면적은 17,119.125px²에서 8,353.862px²로 줄었다. 선형 텍셀 밀도는 69.8559%다.
- 생산 얼굴은 별도 1254×1254 PNG다. GPT 생성 파일→로컬 PNG→생산 GLB의 바이트 SHA가 모두 `9943b2a53752470f41d290466c96fc6aed4b9e7b4bd1a295588b111bc4832e1a`로 같다.
- 그러나 그 GPT 작업은 선명한 승인 원화가 아니라 기존 Blender 앞면을 편집 대상으로 삼았다. 저장된 `prompts/Neutral.txt`는 기존 두 눈을 그대로 보존하라고 명시한다. 따라서 1254 원본 보존은 흐린 눈을 새로 고쳤다는 뜻이 아니다.
- 실제 얼굴 UV 범위는 x=284.052~990.258, y=716.886~1163.996px다. 삼각형 면적 합은 159,863.100px², 텍셀 중심 기준 중복을 제외한 픽셀 수는 155,704개다. 얼굴 전용 PNG 전체의 9.9016%만 사용한다. 이는 머리·배경이 포함된 그림을 그대로 쓰기 때문이다.
- 하이라이트 중앙 인근 7줄을 동일 방식으로 읽으면 20→80% 밝기 경계 폭 중앙값은 생산 원본 4.868px, 승인 D 1.214px다. 이 국소 반사점에서 약 4배 차이가 난다. 서로 구도가 다르므로 전체 화질 점수로 확대 해석하지 않는다.
- `source_eyes_native_pixels.png`는 확대·축소·샤픈 없이 두 원본의 눈 픽셀을 잘라 나란히 놓은 진단 그림이다. 직접 열어 생산 원본의 하이라이트·속눈썹 경계 번짐과 승인 D의 선명한 경계를 확인했다.

이전 `build/face_pilot_measure_session_20261004/measurement.json`의 얼굴 UV 범위·면적·열린 눈 영역의 원본 UV 면적·중앙 하이라이트 경계 수치가 재현됐다. 이번에는 provenance의 삼각형 순서와 원래 정점 인덱스까지 일치함을 확인했고, 별도 텍셀 중심 합집합 계산을 추가했다.

수정은 승인 D의 눈·눈썹·입 픽셀에 맞춰 얼굴 UV를 다시 잡는 방향이 타당하다. 기존 PNG 위 샤픈이나 머리1024 해상도 증가만으로 생산 눈의 원본 붓질은 제거되지 않는다. 승인 D와 기존 얼굴의 눈·입 위치가 다르므로 PNG만 바꿔 끼우면 안 된다.

실제 Roblox 원격 저장 이미지·GPU mip 해상도와 기본/최고 그래픽의 화면 품질은 이 로컬 검사 범위가 아니다. Studio에서 EditableImage가 1024로 열렸다는 사실만으로 업로드 원본이 1024라고 확정하지 않는다. 실제 게임 카메라 비교·새 얼굴 승인·업로드·생산 적용은 별도 확인이 필요하다.
