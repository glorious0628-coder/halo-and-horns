# 진영 선택 E안 구현 인계

작성일: 2026-10-04 KST
승인 원본: `docs/art/verification_2026-10-04/first_impression/faction_pointed_halo_E.png`
사용자 승인: **“좋아 좋아!”**
범위: 구현 전 파일·이미지 조사. 이 조사에서는 게임 소스, 기존 아트, 승인 장부를 변경하지 않았고 업로드·유료 호출을 하지 않았다.

## 1. 승인 범위와 다음 작업

- E의 화려한 세 진영 카드, 둥근 한글, 빛 카드의 위아래 뾰족한 외곽을 구현한다. 이미 승인된 디자인이므로 같은 디자인을 다시 선택해 달라고 묻지 않는다.
- E는 완성 화면 시안이며 현재 게임이 E대로 구현됐다는 증거가 아니다.
- 구현용으로 분리한 새 이미지도 Roblox 업로드 전 직접 검사하고 사용자에게 **한 장씩 표시**한다. 한 번에 10개 이하로 업로드한다.
- `art/out/v1/`은 사용하거나 업로드하지 않는다. 기존 자산과 ID는 보존한다.

## 2. 기존 구성과 높이 문제

### 이미지와 글자는 이미 분리되어 있다

현재 `art/ui/UIP_CardHalo.png`, `UIP_CardHorns.png`, `UIP_CardNeutral.png`를 직접 확인했다. 세 파일은 모두 글씨 없는 RGBA이며, 카드 안의 이름·설명·구호·혜택·선택 버튼 문구는 `FactionPicker`가 별도의 `TextLabel`로 만든다. 버튼의 장식 그림만 카드에 포함되어 있다.

| 진영 | 기존 게임용 PNG 크기 | 버튼 중심의 세로 비율 |
|---|---:|---:|
| 빛 | 635 × 1024 | 0.9090 |
| 뿔 | 617 × 1024 | 0.8570 |
| 장인 | 612 × 1024 | 0.8875 |

근거:
- `src/ReplicatedStorage/Shared/Config.luau:1097`: 기존 카드 ID·크기.
- `src/ReplicatedStorage/Shared/Config.luau:1337`: `Config.UIArt.CardLayout`의 Title/Desc/Motto/Perks/Button 비율.
- `src/StarterPlayer/StarterPlayerScripts/FactionPicker.luau:747`: `buildArtCard()`. 배경·글자·별도 혜택 아이콘·버튼 클릭 영역 생성.
- `art/ui/ui_meta.json`, `art/ui/asset_ids.json`: 로컬 크기와 업로드 ID.

### 현재 정렬은 같은 높이가 아니다

`FactionPicker.luau:1182`의 `prepareCardBalance()`는 **같은 카드 폭과 버튼 중심선**을 우선한다. `placeCards()`는 `ch = cw / c.Aspect`로 카드마다 다른 높이를 구하고 `YFactor`만큼 위아래로 이동한다. 원본 그림을 늘리지 않는 방식이지만, 외곽 높이와 위·아래 끝은 일치하지 않는다.

아래는 **현재 코드와 Config 수치로 계산한 폭 300의 예시**다. 실제 Studio 캡처 실측값이 아니다. 소수점 두 자리로 반올림했다.

| 진영 | 폭 | 높이 | 위쪽 이동량 | 최하단 위치 |
|---|---:|---:|---:|---:|
| 빛 | 300 | 483.78 | 5.73 | 489.51 |
| 뿔 | 300 | 497.89 | 18.80 | 516.69 |
| 장인 | 300 | 501.96 | 0.00 | 501.96 |

같은 버튼선에서도 최하단 차이는 약 **27.18px**다. E용 원본은 같은 캔버스와 같은 외곽/버튼 좌표로 준비하고, 새 정렬은 실제 보이는 상하단을 기준으로 확인해야 한다. 기존 비율에 높이만 강제로 맞추면 버튼과 이름 리본은 여전히 어긋난다.

## 3. 필요한 E 전용 부품 6장

기존 부품은 기능상 재사용할 수 있지만 E의 외곽·장식·비율과 픽셀까지 같지는 않다. 특히 기존 빛 카드의 아랫변은 평평하고 E는 중앙이 뾰족하다. 정확한 E 적용을 위한 권장 분리는 다음과 같다. 이름은 아직 생성·업로드하지 않은 **제안 키**다.

| 제안 키 | 이미지 내용 | 분리 원칙 |
|---|---|---|
| `FactionCardHaloE` | 빛 카드 전체 장식·빈 글자 칸·금색 선택 버튼 | 위아래 뾰족한 외곽 보존 |
| `FactionCardHornsE` | 뿔 카드 전체 장식·빈 글자 칸·빨간 선택 버튼 | E의 뿔·테두리·돌출부 보존 |
| `FactionCardNeutralE` | 장인 카드 전체 장식·빈 글자 칸·청록 선택 버튼 | E의 목재·모루·장식 보존 |
| `FactionTitleRibbonE` | 상단 제목 리본 | 글씨 없음, 투명 배경 |
| `FactionPremisePanelE` | 세 줄 설명판 | E의 각진 금테 보존, 글씨 없음 |
| `FactionFooterPanelE` | 하단 안내판과 E의 제단 아이콘 | 글씨 없음 |

- 각 카드 안의 **혜택 아이콘은 E와 같은 모습으로 카드 PNG에 포함**하는 최소 분리안을 권장한다. 이 경우 새 카드에 한해서 기존 별도 아이콘과 점 대체 표시를 끄되, 혜택 글자는 그대로 분리한다.
- 하단 제단 아이콘을 안내판에 포함하면 기존 `note.Icon`을 새 안내판에 중복 표시하지 않는다.
- 선택 버튼은 현재처럼 카드 PNG에 포함하고 투명 클릭 영역과 별도 글자/잠금 표시를 사용한다. 새 버튼 영역을 `CardLayout`에 다시 기록한다.
- 세 카드의 캔버스 크기·알파 경계·제목/본문/버튼 기준선을 공통으로 준비한다. E에서 단순히 저해상도 크롭한 이미지를 확대했다고 원본 세부가 증가한 것으로 보고하지 않는다.
- 설명판·하단판의 9-slice 사용 여부와 안전한 중앙 영역은 새 파일을 직접 보고 정한다. 기존 패널의 Slice 좌표를 복사하지 않는다.
- 6장은 제작 방안이지 완료 수량이 아니다. 다른 방식으로 아이콘을 별도 추출한다면 부품 수가 늘어나므로 장부와 업로드 배치를 다시 계산한다.

## 4. 공유 자산을 덮으면 다른 화면이 바뀐다

**기존 `CardHalo`, `TitleRibbon`, `PanelParchment`의 ID·크기를 E로 덮지 않는다.** E용 키를 추가하고 `FactionPicker`에서만 매핑하는 범위가 안전하다.

| 공유 키 | 실제 사용처와 영향 |
|---|---|
| `CardHalo` | `Panels.luau:1080`의 닉네임 저장 버튼. 원본에서 `ImageRectOffset=(94,876)`, `ImageRectSize=(448,112)`를 잘라 쓴다. 새 카드로 덮으면 잘못된 그림이 나온다. |
| `TitleRibbon` | `ClassPicker.luau:711` 및 `Panels.luau:1055`. 전역 교체 시 직업 선택과 닉네임 창까지 바뀐다. |
| `PanelParchment` | HUD, VitalsUI, EventHUD, Panels, ClassPicker에서 공유한다. 전역 교체 시 다른 패널·버튼 외곽까지 바뀐다. |

최소 소스 범위는 `Config.luau`의 **E 전용 키·영역·글꼴 설정 추가**와 `FactionPicker.luau`의 **그 설정 연결·레이아웃·글자 스타일**이다. 실제 부품 경로·크기는 `art/ui/ui_meta.json`, 업로드 후 ID는 `art/ui/asset_ids.json`에도 기록한다.

## 5. 둥근 한글과 한영 전환

### E의 실제 글꼴 이름은 아직 확정하지 않았다

- GPT 그림의 둥근 한글 형태는 승인됐지만 그 픽셀만으로 Roblox에서 쓸 수 있는 특정 글꼴 패밀리/ID가 확정되지는 않는다.
- `UIKit.luau:23`은 공통 글꼴 ID `12187370747`을 사용한다. 기존 기록상의 Noto Sans이며 `UseTextImages=false`다.
- `FactionPicker.luau:291`의 `applyFont()`는 제목을 Bold, 나머지를 Regular로 바꾼다. Enum.Font 이름만 바꿔서는 E의 둥근 한글이 구현되지 않는다.
- `UIKit.luau:129`의 `themeFontFace()`는 명시한 `Font` 객체를 그대로 반환한다. `watchFont()`도 명시적인 사용자 FontFace를 보존한다. 따라서 **진영 화면에서만 전용 FontFace를 전달**하면 공통 UIKit 폰트를 전역 변경하지 않아도 된다.
- 후보 글꼴의 한글·숫자·영어 지원, 실제 엔진 표시, E와의 글자 형태, TextBounds를 확인한 뒤 확정한다. 현재 조사는 후보 패밀리나 ID를 검증한 결과가 아니다.

### 글자를 카드 이미지에 통째로 넣지 않는다

- 이름·설명·구호·혜택·버튼·하단 안내는 별도 `TextLabel`로 유지한다. E의 이미지에서 글자를 지운 아트 위에 실제 글씨를 배치한다.
- `docs/RELEASE_PLAN.md`는 같은 경험 안에서 한국어/영어를 지원하고 `LocalizationTable`에 번역을 넣도록 한다.
- 조사 시 `src/`에서 `Localization`, `AutoLocalize`, `RootLocalization`, `Translator`, `GetTranslator`가 검색되지 않았다. 이는 **소스에 명시된 연결을 찾지 못했다**는 뜻이며 Studio 내부 설정까지 검사한 결과는 아니다.
- 따라서 글씨 분리나 E 구현만으로 한영 기능 완료라고 기록하지 않는다. 로케일별 번역·긴 문장·동적 수치·ko/en Studio 검증은 별도 작업이다.
- 기존 `BindArtText()`를 전역으로 다시 켜면 예전 C 글자 이미지가 나타날 수 있으므로 E 구현 수단으로 사용하지 않는다.

## 6. 실제 적용 후 필수 확인

1. **그림 정렬:** 각 PNG의 알파 경계 기준 상단·하단·높이, 제목 리본, 버튼 중심선 차이를 숫자로 기록한다. 장식까지 포함하며 이미지 캔버스 크기만 비교하지 않는다.
2. **엔진 정렬:** 기본 데스크톱, 낮은 높이, 휴대폰에서 같은 항목을 실제 렌더 좌표로 확인한다. 화면 캡처 크기와 Roblox `ViewportSize`/UIScale 차이를 함께 기록한다.
3. **텍스트:** 실제 FontFace, 글자 크기, TextBounds, 잘림/줄바꿈, 모든 세 줄 설명과 하단 안내를 확인한다. 영어 문장 확인은 번역 연결 이후 별도 완료로 기록한다.
4. **클릭:** 버튼 클릭·선택 잠금·최소 44px 터치 영역·빠른 두 번 누르기 방지가 유지되는지 확인한다. 그림 버튼과 실제 클릭 영역이 맞아야 한다.
5. **로딩 실패:** E 자산 ID가 없거나 로드되지 않을 때 기존 IMG-R4 코드 대체 화면과 글자가 남는지 확인한다.
6. **공유 화면:** 닉네임 저장 버튼, 직업 선택, HUD·물약·기존 패널이 영향을 받지 않았는지 확인한다.
7. **배경:** 배경은 실제 Roblox 마을을 사용한다. E 스크린샷을 화면 배경으로 붙이지 않는다. 월드 이름표·간판·채팅 정리가 필요하면 로컬 선택 화면이 열린 동안만 숨기고 닫을 때 원래 상태를 복원한다. 이 조사에서 해당 동작을 구현·검증하지는 않았다.
8. **기록:** 새 아트 SHA·영역 좌표·Studio 캡처·숫자 JSON을 이 검증 폴더에 남긴다. GPT 시안 승인과 실제 게임 구현 합격을 구분한다.
