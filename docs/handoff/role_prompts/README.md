# 역할 프롬프트 폴더 (검수가 관리)

> **2026-10-11 Codex 인계 갱신:** 사용자가 담당 작업 세션을 아직 새로 만들지 않았다고 확인했다. 아래 '8개 상시'는 역할 구성이고 실제 실행 세션 수가 아니다. 최신 상태·전달 대기는 `../review_handoff_2026-10-11d.md`와 `../state/review.md`를 먼저 읽는다. 본문의 과거 완료·세션 생성 기록·모델 표는 당시 Claude 설정이며, Codex에 같은 모델을 설정했다고 간주하지 않는다. 옛 도구 이름 대신 현재 제공되는 도구를 사용한다.

새 세션을 만들 때 이 폴더의 역할 파일을 열어요. 최신 인계를 먼저 읽고 역할별 다음 일을 확인해요. 모델·노력은 현재 앱에서 제공되는 설정으로 정하며, 아래 옛 모델을 임의로 다른 모델에 대응시키지 않아요.

- 이 폴더는 **'모든 것 검수' 세션이 관리해요.** 역할, 큐, 규칙이 바뀌면 검수가 해당 파일을 고치고 push해요.
- 세션 id는 적지 않아요. 현재 세션 목록 도구(Codex: `list_threads`)로 같은 저장소/worktree의 '모든 것 검수'를 찾아요. 다른 게임의 같은 이름 세션은 제외해요.
- 세션 순서: **검수 먼저** → 메인 반영 1 → 게임성 개발 1·2·3 → 이미지 개발 → 이미지 생성 1·2 → 소리 만들기(배경 음악, A23-100) → (쉬는 차례: 촬영 편집 — 사용자 10/10: ③ 교차로가 디자인·게임성 모두 끝난 뒤에 세션을 만들어 찍음, A23-102).

**세션 줄이기(사용자 10/11 "12월 1일 베타니까 세션 좀 줄여도 될 것 같지?" → 검수 결정):** 늘 일하는 세션은 8개예요. 검수, 메인 반영 1, 게임성 개발 1·2, 이미지 개발, 이미지 생성 1·2·3.
- **게임성 개발 3 → 쉬기.** 지금 하던 검증(dev2-hint·skillq)만 끝내고, 남은 서버 큐는 게임성 개발 2가 이어받아요. 게임성 개발 2의 브랜치 검증은 검수가 시험·워크플로로 하고 합쳐요.
- **소리 만들기 → 부를 때만.** 스킬 소리 42개 올리기, 몬스터 죽는 소리처럼 묶음이 생기면 검수가 깨워요.
- **촬영 편집 → 계속 쉼.** 교차로가 끝나면 다시 만들어요.
- **사용자 "너가 세션들 삭제도 해줘"(같은 날):** 소리 만들기 세션은 지웠어요(파일 42개·슬라임 소리는 origin에 있음, 07764413·86cd4a69). 게임성 개발 3도 마무리(검증·인계 문서)가 끝나면 지워요. 다시 필요하면 이 폴더의 파일(09_sound.md, 04_dev3.md)로 새로 만들어요.

**큰 일은 Anthropic API로(사용자 10/11 "큰 작업 하되, 앤트로픽 API로 SDK로 진행"):** 큰 코드·검토·판정·긴 문서는 `py tools/api_agent.py`(읽기 모드, 또는 `--write --branch api/<이름>` 쓰기 모드)로 맡기고, 세션은 지휘·확인·시험과 앱 도구 일(Studio·브라우저·Blender·Tripo 실행)만 한다. api/* 브랜치는 검수가 임시 worktree에서 시험한 뒤 병합한다. 할로윈(호박밭·유령 숲) 시험은 병합 조건이 아니다(사용자 10/11: 내년 10월).

**모델·노력은 일마다 다시 맞춘다(사용자 10/11 "그때그때마다 … 작업 하는 내용이 바뀔 수가 있잖아"):** 아래 표는 기본값이다. 검수는 세션에 새 일을 줄 때마다 그 일에 맞게 모델·노력을 바꾼다(올리기·적용·사진 → Sonnet, 어려운 3D 모양·복잡한 서버 → Opus xhigh, 보통 코드 → Opus high). 주간 사용량도 본다.
