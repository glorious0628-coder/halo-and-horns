## 1. 한 줄 요약과 원칙

**한 줄 요약:** 부서진 왕관 조각 하나의 행방을 따라간다.
- 조각은 초원 슬라임이 먹은 **가루** → 분수 위 **조각** → 고블린이 훔친 **조각** → 옛 왕국의 **큰 조각**으로 커진다.
- 장마다 같은 질문을 더 큰 조각으로 다시 묻는다: **"돌려줄까(천사·고친다), 가질까(악마·차지한다)?"**
- 이 질문은 이미 있는 `FactionLore` 그대로다. 빛은 "지키고 고친다", 뿔은 "빼앗아 차지한다"이다.

### 3-1. 선악 점수 흐름 (빛·뿔이 한쪽으로만 고른 경우, 결정 3 추천안)

| 순간 | 점수 | 누적 |
|---|---|---|
| S0 정화/삼킴 (약 9분) | +2 | 2 |
| S3 금빛 젤리 (우연, 10~25분) | +1 | 3 |
| S1 거위 첫 참여 | +1 | 4 |
| M2-3 분수 (약 17분) | +2 | 6 |
| S6 진영의 길 (베타 선택) | +1 | 7 |

| M4-4 큰 조각 | +3 | 13 |

- 메인과 S0만 해도 7점이다. 이야기만으로 계급 2에 닿으려면 서브를 1~3개 해야 한다.
- 보수적인 안: 모든 선택 +2, 3장 선택 제외 → 베타 합계 6 이하. 이 경우 이야기만으로는 계급이 오르지 않는다.

**반대편을 골랐을 때 (결정 4 추천안)**
- 점수는 고른 쪽으로 준다(A23-2): 빛 진영이 삼키면 악명이 오른다.
- 토스트: "조각이 어둠 쪽으로 기울었어요 (악명 +2)" / "조각이 빛 쪽으로 기울었어요 (명예 +2)".
- 안내자 반응 한 줄:
  - 빛 안내자: "음… 그것도 당신 선택이에요."
  - 뿔 안내자: "착하게 갔네? 그것도 네 맘이야!"
- 칭호 규칙(자기 진영 점수만 셈)은 바꾸지 않는다. 선택은 `Pick`에 남겨 나중 대사 말투에 쓴다.

### 6-2. `StoryQuestService` (새 서버 모듈, 체인 엔진)

- **파일:** `src/ServerScriptService/StoryQuestService.luau`. `Init(S)` / `Start()` 규칙을 따른다.
- **등록:** `Main.server.luau`의 두 고정 목록에 넣는다(넣지 않으면 로드되지 않는다). 새 원격 `StoryAction`은 `Net.Names`와 `Config.RateLimits.StoryAction`에 추가한다.
- **진행 훅** (Start에서 연결):
  - `MonsterKilled`: Kind, ZoneId, Golden, Position, WarPoints, WarShare, Personal
  - `Released`: Auto, MonstersHit, Healed
  - `GoldEarned`: source
  - `ZoneChanged`
  - `LeveledUp`
  - `GooseFinished`
  - `PlayerKO`
  - `KaijuStarted` / `KaijuEnded`
  - `SackResolved` (정식)
  - `FactionChanged`, `Rebirthed`, `LevelReset`, `ClassChanged`
  - 1초 상태 확인: `BlacksmithVisited`, `WeaponOwnedMask`, `AutoCombatEnabled`, `HPPotionCount`, `CarriedGold`, `PvPService.IsRookie`, `WarService.GetPersonalPoints`, GameState `GooseNextAt`. QuestService의 1초 루프를 함께 쓰거나 같은 방식으로 돈다.
- **단계 흐름:**
  1. 단계를 켠다. `Enter` 목표면 현재 지역을 바로 확인한다.
  2. 진행을 센다.
  3. 목표 수에 닿으면 **다음 단계를 먼저 저장**한다.
  4. G1을 지급하고(`ProgressionService.AddBankGold(p, n, "Quest")`), 토스트를 띄운다.
  5. `Panel` 단계면 `OpenPanel(player, "Story", id)`를 보낸다.
  - 장 끝은 `Claimable` 상태로 둔다. [받기]를 누르면 `Done`을 먼저 적고, 그다음 골드·XP를 지급한다(CR-M6 레벨 상한, CR-M24 받기 잠금을 재사용).
- **`StoryAction(questId, action, option)` 검증:**
  - 인자는 문자열이다. Id는 표에 있는 것만 받고, action은 `"Talk"`/`"Choose"`, option은 `"Good"`/`"Evil"`(장인 `"A"`/`"B"`)만 받는다.
  - 지금 활성 단계가 그 Talk·Choice 단계인지 확인한다.
  - 준비·생존·직업 선택 상태를 확인하고, 호출 간격을 제한한다.
  - 선택은 `Pick`을 먼저 저장한 뒤 점수를 준다. 점수는 빛·뿔만 받고 `PlayerService.AddStat(p, "Honor"|"Infamy", n)`로 준다.
- **S0 완료 시:** `CombatService.UnlockAutoCombat(player)`를 부르고, `Pick.S0 = "Purify"|"Devour"`를 저장한다(A23-2의 `ShardChoice`가 이것이다).
- **QuestService 쪽 작은 수정:**
  - `tutorialEntry`의 99단계 분기를 바꾼다.
    - 진행 중인 메인이 있으면 메인 행을 낸다.
    - 레벨 때문에 잠긴 메인이면 잠김 줄을 낸다.
    - 둘 다 없으면 지금처럼 `VisitBlacksmith`/`nextGoalText`를 낸다. 화면이 비지 않게 하기 위해서다.
  - `onClaimQuest`가 `"story:<id>"`도 받게 한다.
  - 공개 함수 `QuestService.MarkDirty(player)`를 추가한다.
  - 원격은 지금처럼 `"Quests"` 하나에 모두 실어 보낸다.

### 6-3. 저장 형식과 옛 세이브 이전

```lua
-- Config.Data.Defaults에 추가 (Config.Data.Version은 2 그대로: 올리면 옛 서버가 새 기록을 거부함)
Story = { M = "", St = 0, P = 0, T = {}, Claim = false, Subs = {}, Done = {}, Pick = {}, Legacy = false },
-- Subs = { S0 = { St = 2, P = 1, T = { a = true, b = true } } }   -- 순서 무관 하위 목표는 T
-- Done = { M1_1 = true },  Pick = { S0 = "Purify", M2_3 = "Good" }
```

- **DataStore 규칙:** 문자열 키 딕셔너리만 쓴다. 섞인 배열은 쓰지 않고, Id는 짧게 한다.
- **정리:** `fillDefaults`는 최상위 키만 채운다. 그래서 `sanitizeStory(d)`를 `onPlayerReady`에서 `ensureSlots`처럼 부른다.
  - 모르는 Id는 버린다.
  - St와 P 범위를 맞추고, 서브 수 상한과 타입을 바로잡는다.
- **옛 세이브 이전:** `TutorialStep` 이전과 같은 방식(`DataService.luau:364-374`)을 쓴다.
  - 저장 기록에 Story 키가 없으면, 기본값을 채운 뒤 `Legacy = true`로 표시한다.
  - 준비가 끝나고 `TutorialStep == 99`일 때 레벨에 맞는 장에서 시작한다.
    - Lv10 미만: M1-1.
    - Lv10~24: 1·2장을 `Done`으로 표시하고 M3-1부터.
    - Lv25 이상: 3장까지 `Done`으로 표시하고 M4-1부터. 베타에서는 4장이 없으므로 다음 목표 줄로 대신한다.
  - **지난 장 보상과 선택 점수는 소급하지 않는다.**
  - S0은 `AutoCombatUnlocked=false`인 모두가 받을 수 있다.
  - 이전이 끝나면 `Legacy = false`로 바꾼다.
- **첫 임무 상태 기계**(`TutorialStep`, `TutorialKills`)는 그대로 둔다. 체인은 99단계부터 시작한다.
- **환생·무료 직업 변경**(레벨 1로 돌아감): Story는 유지한다. 레벨 조건이 있는 메인은 잠김 줄로 보이고, `Done` 덕분에 반복 보상은 없다.
- **진영 변경:** 메인은 대사만 진영별로 바뀐다. 진행 중인 진영 전용 서브는 빠진다. `Pick`은 남는다. 제단 무료 변경이 점수를 지우는 것은 기존 "배신의 대가" 규칙 그대로다.

### 6-4. HUD 표시 규칙 (메인 1 + 서브 최대 N, 폰 한 줄)

- **서버가 보내는 순서:** [첫 임무 또는 메인 (Pinned)] → [서브 최대 `MaxSubs`] → [일일·추가 3칸].
- **서브 우선순위:** 받기 가능 > 상황형(지금 할 수 있는 거위·괴수·동료) > S0 > 지금 지역의 서브 > 나머지.
- **PC:** 접힌 상태는 머리줄 + 메인 1행, 펼치면 전부 보인다. 배지는 `TXT.BadgeMain="메인"`, `TXT.BadgeSub="선택"`이다.
- **폰 한 줄 우선순위:**
  1. 첫 임무(받기 전까지, A23-3)
  2. 받기 가능한 이야기
  3. **지금 있는 지역의** 메인 단계
  4. 지금 지역의 서브
  5. 다른 지역의 메인("→ 교차로")
  6. 일일
  - 형식은 "1/2 왕 슬라임"처럼 진행 숫자가 앞에 오고, 14자 안팎이다.
  - 3번 규칙은 메인이 교차로를, S0이 초원을 가리키는 충돌(F4)을 막는다.
- **폰 오버레이:** 메인 1 + 서브 1 + 일일 3 = 5행이다. 넘치면 `ScrollingFrame`을 쓴다. 5행이 실제로 들어가는지 Studio 스크린샷으로 확인한다.
- **받기:** 이야기 행은 `e.Id`를 보낸다(`"story:<id>"`). 받기 가능 개수에 메인과 서브를 포함한다.
- **줄 누르기:** `L.PinnedTap`을 `L.StoryTap(e)`로 일반화하고, 서브 행도 누를 수 있게 한다.
  - Talk·Choice 단계: 대화창을 다시 연다.
  - Guide에 지역이 있으면: `findTravelTarget` + 이동 패널 + 빔.
  - Blacksmith: 모루 빔.
- **빔 대상:** 지역 이동 대상, 모루, `CrownShard` Model 안의 BasePart, 진영 마을, 연못, 야영지. 왕 슬라임 언덕은 힌트로만 쓴다.
- **지역 변수 한도:** HUD는 최상위 local이 약 148개다. 새 상태는 `questState`/`L`/`TXT` 표 안에만 넣는다.

### 6-5. 대화창 재사용

- `BUILDERS.Story`는 `BUILDERS.Welcome`(`Panels.luau:1154+`)을 일반화한 것이다.
  - 말하는 이 이름과 쪽 단위 대사(1~2줄)를 보여 준다.
  - 버튼은 [다음] / [계속] 또는 **선택 버튼 2개** / [나중에]다.
  - 창 제목은 "말하는 이 · 퀘스트 제목"으로 바뀐다.
  - **초상화는 항상 숨긴다.** 옛 치비 그림은 Firefly 교체 때 삭제될 대상이기 때문이다.
- `OpenPanel:FireClient(player, "Story", questId)`처럼 두 번째 인자를 쓴다. `Panels.Open(id, arg)`로 바꾸고, 인자 없는 기존 호출은 그대로 동작한다.
- 오프닝과 선택 화면 동안에는 Welcome처럼 `PendingOpen`으로 미룬다.
- 선택 버튼은 기존 `UIKit.ArtButton`이나 코드 대체 그림으로 만든다. **새 그림은 없다.**
- 닫기는 선택이 아니다. 줄을 누르면 다시 열린다.
- 중간 단계는 대화창 대신 `Net.Notify` 토스트 1줄로 알린다.
