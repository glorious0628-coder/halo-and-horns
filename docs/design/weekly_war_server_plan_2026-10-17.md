## 1. 플레이어 저장 (data.War = 새 칸 하나, 평평한 숫자만 — 옛 서버도 keepExtra로 지킴, 판 안 올림)
| 키 | 뜻 |
|---|---|
| WW | 세는 주(Config.WeekIndex) |
| WF | 그 주 첫 유효 활동 진영("Halo"/"Horns", 한 갈래 고정 — 주 중간에 바꾸면 새 진영 몫은 0, 장인 주간 선물과 겹쳐 받지 않음) |
| WP | 그 주 진영 기여 ×100 (정수; 진영 풀에 실제로 들어간 양 = AddPoints의 poolN, AddKill의 pool/per) |
| WM | 그 주 인정 활동 분 |
| WD / WDM | KST 날(Config.DayIndex) / 그날 인정 분(60에서 멈춤 — 점수·분 같이 멈춤) |
| WB / WBN | 마지막으로 센 10분 구간 번호 / 서로 다른 구간 수(2 이상 = 자격 조건) |
| WE | 자격 넘은 표시(true; 서버 합산에 '유효 계정 +1'을 한 번만) |
| WGW / WGR | 마지막 주간 결과 받은 주 / 결과("Win"·"Lose"·"Draw"·"Few") |
| WGift_<item> | 못 준 개수(HP·MP·Enh70) — 장인 선물과 같은 방식(물약 99·아이템 99 넘으면 기다림) |

활동 1분 인정 = 그 분 안에 (a) 서버가 확인한 진영 기여(풀 증가) + (b) 본인 조작 PlayerService.GetLastOwnActive 60초 안. 이동·입력만·맞기만 = 0.
행사 점수(AddFactionPoints: 거위·괴수)는 사람 몫이 없어서 v1에선 주간에 안 넣음(행사 ID·참여자 기록 생기면 다음에).

## 2. 서버 합산 (DataStore "WeekWar", 시즌·주·조각)
- 서버마다 메모리 모음(진영별 P·M·유효 계정 수) → 60초마다 조각 키 `S<시즌>:W<주>:<0..7>`(서버 JobId 해시로 고정 조각)에
  UpdateAsync로 더함. 묶음 ID = JobId:순번, 조각 문서에 서버별 마지막 순번 저장 → 같은 묶음 두 번 안 더함(재시도 안전).
- 마감: 월 00:10 뒤 아무 서버나 8조각 읽어 합 → 결과 키 `R<시즌>:W<주>` UpdateAsync '처음 쓴 것만'(이미 있으면 그걸 씀).
  최소 표본(양쪽 유효 계정 10 + 활동 120분) 못 넘으면 "Few"(일반만). 표시 점수 소수 둘째 자리 같으면 "Draw".
  조각 읽기 실패 = 결과 미루기(1분 뒤 다시), 0으로 보고 확정하지 않음.
- 개인·Studio·예약 서버 = 합산 안 함(RankingService와 같은 판정). Studio 메모리 모드 = 결과 키도 메모리.
