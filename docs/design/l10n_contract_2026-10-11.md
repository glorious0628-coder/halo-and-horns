# 한국어 모드 — 클라·서버 글 계약 (게임성 개발 1, 2026-10-11, SPEC A23-111)

> 검수 요청(10/11): `l10n_client_2026-10-10.md` 설계를 **계약으로 확정** — 글 키 방식(TextKo / UIKit.Tx)과 서버가 키로 보내는 모양. 개발 2의 한국어 서버가 이 문서를 기다린다. **코드는 이 계약 승인 뒤**, 구현 순서는 A23-111대로 빛 마을 뒤.
> 이 문서가 `l10n_client_2026-10-10.md` §2·§3·§6보다 새것이다(§4 번역 목록·§5 글꼴은 그대로).

## 0. 한 줄 요약
- 영어 원문은 **지금 있는 글 표 그대로**(Config.*.Text, 모듈 TXT). 한국어는 **`Shared/TextKo.luau` 한 파일**(키 → 한국어).
- **키 = 그 글이 사는 표의 경로 + 칸 이름**(`"Config.Text.GooseReward"`).
- 플레이어 언어 = 서버가 정하는 **플레이어 속성 `Lang`**(`"en"`/`"ko"`).
- 서버 → 클라 글은 **완성 문장이 아니라 `{ Key, Args }`**. 클라가 자기 언어로 만든다(같은 서버에 한국어·영어 플레이어가 섞여도 각자 자기 말로).

## 1. 언어 정하기 (서버가 정함 — 개발 3/2: SettingsService)
- 저장 칸은 그대로: `Settings.Lang` = `"Auto"` | `"ko"` | `"en"`(Config.Settings.Defs.Lang, 지금 있음).
- 서버가 **`player:SetAttribute("Lang", "ko" | "en")`**:
  - 저장값이 `"ko"`/`"en"`이면 그것.
  - `"Auto"`면 `player.LocaleId`(서버에서 읽힘)가 `"ko"`로 시작하면 `"ko"`, 아니면 `"en"`. **새 원격 없음.**
  - 접속 때(저장 불러온 뒤) 한 번 + 설정 저장(SetSettings) 때마다.
- 클라 `UIKit.Lang()` = 속성 `Lang`(없으면 같은 규칙을 클라에서: 저장값 → `LocalizationService.RobloxLocaleId`). 속성이 오기 전 첫 화면도 맞게 보이게 하려는 것.
- 바뀌면 클라 `UIKit.LangChanged`(Signal) → 열린 창 다시 그리기, HUD 글 다시 쓰기(구현 몫, 개발 1).

## 2. 글 키
- **키 = `"<표 경로>.<칸>"`**, 표 경로는 코드에서 그 표를 부르는 이름 그대로:
  - Config: `"Config.Text.BullyAutoOff"`, `"Config.Skills.Text.NeedMP"`, `"Config.Factions.Halo.Name"`, `"Config.Factions.Halo.Perks.1"`(배열은 번호).
  - 클라 모듈 표: `"<모듈>.<표>.<칸>"` — `"HUD.TXT.Bag"`, `"SkillBook.T.Text.Title"`, `"PetWindow.T.Text.Follow"`.
- 영어 원문은 키 경로로 찾는다(Config는 Config 표를 따라 내려감, 모듈 표는 모듈이 `L10n.Register("HUD.TXT", TXT)`로 한 번 등록).
- 옛 `xxxEn` 쌍둥이 칸(`PlayerEn` 등)은 **영어 원문으로 읽기만** 하고 새로 만들지 않는다. 키는 `En` 없는 이름(`"…Player"`).
- 칸 이름을 바꾸면 키가 바뀐다 → `TextKo`도 같이 바꾼다(시험이 잡음, §7).

## 3. 공용 모듈 `ReplicatedStorage/Shared/L10n.luau` (개발 1이 만듦, 서버도 씀)
| 함수 | 뜻 |
|---|---|
| `L10n.Get(key, lang)` | `lang == "ko"`이고 `TextKo[key]`가 있으면 그것, 아니면 영어 원문(키 경로), 없으면 `key` 자체(빈칸 대신 눈에 띄게) |
| `L10n.Format(template, args, lang)` | 자리 채우기(§4) |
| `L10n.T(key, args, lang)` | `Format(Get(key, lang), args, lang)` |
| `L10n.Msg(msg, lang)` | `{ Key, Args }` 하나를 글로(§5, Args 안의 `{Key,…}`도 차례로) |
| `L10n.Register(path, tbl)` | 모듈 표 등록(클라 모듈 Init에서 한 번) |
- 클라 `UIKit.Tx(t, key, ...)`는 남긴다: 등록된 표면 `L10n.T("<경로>.<key>", {...}, UIKit.Lang())`, 등록 안 된 표면 지금처럼 영어. 그래서 화면을 하나씩 옮겨도 안 깨진다.

## 4. 자리(`%s`·`%d`) 규칙
- 영어 원문은 지금처럼 `%s`·`%d`·`%.1f`(코드 그대로).
- 한국어는 **같은 자리를 같은 수만큼**. 순서를 바꿔야 하면 `{1}`·`{2}`(args 번호)를 쓴다 — `L10n.Format`이 둘 다 받는다(한 글 안에 섞지 않음).
- `Config.Plural`(1 monster / 2 monsters)은 **영어일 때만** 부른다. 한국어는 단수·복수 없음.
- 숫자는 **서버가 숫자 그대로**(문자열로 미리 꾸미지 않음) 보내고, 클라가 `Util.FormatNumber`로 쓴다(천 단위 쉼표는 두 언어 같음).

## 5. 서버 → 클라 모양 (개발 2·3 몫)
### 5-1. 메시지 하나 = `{ Key = "<키>", Args = { ... } }`
- `Args`는 **배열**(자리 순서 = 영어 원문의 `%` 순서). 한 칸은:
  - 숫자 → 숫자 그대로,
  - 사람 이름(플레이어 표시 이름, 별명) → 문자열 그대로(번역 안 함),
  - **번역할 이름**(진영·직업·몬스터·물건·구역 이름) → `{ Key = "Config.Factions.Halo.Name" }`(Args 없는 메시지). 클라가 자기 말로 바꿔 끼움.
- 예: 거위 보상 `Net.NotifyKey(p, "Config.Text.GooseReward", { gold, xp }, "reward", nil, "GoldPickup")`
  → 줄: `{ Key = "Config.Text.GooseReward", Args = { 120, 300 }, Kind = "reward", Sound = "GoldPickup" }`.
- 예: 진영 바꿈 `{ Key = "Config.Text.SwitchDone", Args = { { Key = "Config.Factions.Horns.Name" } } }`.

### 5-2. 통로별
| 통로 | 지금 | 계약 |
|---|---|---|
| `Notify` (Net.Notify 51곳, NotifyAll 14곳) | `{ Text = 영어 완성 }` | **새 `Net.NotifyKey(player, key, args, kind, duration, sound)` / `Net.NotifyAllKey(key, args, …)`** → `{ Key, Args, Kind, Duration, Sound }`. 옛 `Text` 줄도 받는 동안은 클라가 그대로 보여 줌(옮기는 동안만). **NotifyAll은 받는 사람 언어가 섞이므로 반드시 Key 방식.** |
| `Announce` | 이미 `{ Key, Args }`(Key = `Config.Announce.Text`의 칸) | 그대로. 클라가 `"Config.Announce.Text." .. Key`로 찾음. Args 안 이름은 5-1 규칙(`Banter`처럼 서버가 지은 문장은 Key 방식으로 바꿈). |
| `Quests` | 줄마다 `Text = 영어` | 줄마다 **`TextKey` + `TextArgs`** 더함(`Text` 영어는 기록·시험용으로 남김). 클라는 `TextKey`가 있으면 그걸 씀. 튜토리얼 줄(`TUT_MESSAGES.*`)도 키로. |
| `OpenPanel("Story", {Id,…})` | id만 | 그대로(클라 표). |
| `Board`, `Rankings`, `PetList`, `NicknameResult`, `Inventory` | 숫자·id·이름 | 보이는 글 칸이 있으면 같은 `Key/Args`, 사람 이름은 그대로. |
| BillboardGui·SurfaceGui 글(서버가 만든 머리 위 글·간판) | 영어 Text | 서버는 **속성 `TextKey`(+`TextArgs` JSON)** 를 달고 영어 Text를 넣는다 → 클라가 자기 언어로 덮어씀(누구나 보는 것이라 Key 방식만 가능). |
| 채팅 줄(TextChatService 시스템 줄) | 클라가 만듦 | 클라가 자기 언어로(지금 Announce와 같음). |
- 서버가 받는 사람 언어로 직접 문장을 만들지는 않는다(`player:GetAttribute("Lang")`로 만들면 언어를 바꿀 때 다시 보내야 하고, 모두에게 보내는 것엔 못 씀). **예외 없음** — 서버 로그·시험용 영어는 `L10n.T(key, args, "en")`로.

## 6. 한국어 표 `Shared/TextKo.luau`
- `return { ["Config.Text.GooseReward"] = "거위가 골드 %d · 경험치 %d를 줬어요!", ... }` — 평평한 표 하나, 키 순서 정렬.
- 직접 고치지 않는다: `docs/l10n/strings_ko.json` → `py tools/l10n_apply.py`가 씀(§4 of `l10n_client_2026-10-10.md`). 번역 초안·용어집·검토 = 검수.
- 고정 큰 글 그림은 이 표가 아니라 `Config.UIArt` 부품의 `IdKo`(그대로).

## 7. 시험 (구현 때 같이 — `tools/test_l10n.py`)
1. `TextKo`의 모든 키가 영어 원문에 있다(경로로 찾아짐).
2. 같은 키의 `%` 자리 수(또는 `{n}` 최대 번호)가 영어와 한국어가 같다.
3. 서버 코드의 `NotifyKey`/`NotifyAllKey`/`TextKey` 키 글자가 모두 영어 원문에 있다(정적 검사).
4. `L10n.Msg`: 숫자·사람 이름·`{Key}` 이름 칸, 없는 키 → 키 글자, ko 없는 키 → 영어.
5. `Lang` 정하기: 저장 ko/en, Auto + LocaleId `ko-kr`/`en-us`.
6. 변이 검사(자리 순서 뒤집힘, ko 우선 빠짐 등).
