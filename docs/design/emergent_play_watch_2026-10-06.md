# 플레이어가 스스로 만든 재미 보기 (사용자 공유 글, 2026-10-06)

사용자가 좋다고 한 글의 요점: 《Cow Clicker》는 공허한 반복을 풍자하려 만든 게임인데도 5만 6천 명이 했고, 이용자들이 **스스로 목표(공략·순위 경쟁·관계)**를 만들었다. 반복 플레이를 콘텐츠 부족이나 보상 설계로만 보지 말고, **사람들이 무엇을 비교하는지, 어떤 공략을 나누는지, 목표를 끝냈는데 왜 다시 오는지**를 본다. 테스트에서는 "재미있나요?"와 함께 **"다시 들어와서 무엇을 하고 싶었나요?"**를 묻는다.

## 우리 베타에 넣는 것
1. **베타 의견(BB41)의 질문 두 개:** ① "재미있었어요?" (별 1~5) ② "다시 들어오면 뭘 하고 싶어요?" — 고르기(사냥·강화·랭킹·친구랑 싸우기·펫·꾸미기·탐험·기타) + 짧은 글(선택, TextService 필터, 개인정보 묻지 않음). KO/EN 문구는 중앙 표에.
2. **지표(BB38)에 '스스로 만든 목표' 신호 추가:**
   - 다시 들어온 뒤 처음 3가지 행동(어디로 가는지, 어느 창을 여는지).
   - 일일 퀘스트·메인 퀘스트를 다 끝낸 뒤에도 30분 넘게 노는 사람이 무엇을 하는지(사냥터·강화·PvP·대기).
   - 비교 행동: Tab 목록 열기, 랭킹 탭별 열람 수, 다른 플레이어 살펴보기(BB20이 있으면), 같은 자리에 모이기.
   - 의도하지 않은 반복: 같은 물건·NPC·장소를 계속 누르거나 같은 행동을 반복하는 것(예: 분수 주변 맴돌기, 거위 둥지 대기, 특정 몬스터만 잡기).
   - 개인정보 없이 AnalyticsService 커스텀 이벤트로만, 서버당 묶어서.
3. **사람과 하는 테스트(10/25~30 테스트 주, 친구·가족):** 끝나고 두 질문을 그대로 묻고 답을 `docs/review/playtest_answers_2026-10-2x.md`에 적는다. 답에서 다음에 만들 기능 후보를 `docs/design/idea_backlog.md`로 옮긴다.
4. **베타 뒤 1주 보고:** 위 신호에서 "우리가 만들지 않았는데 사람들이 하는 것" 3가지를 뽑아 사용자에게 짧게 보고 → 정식 전에 키울지 정한다.

담당: BB38·BB41 = 게임성 개발 1(클라이언트 창)·게임성 개발 2(서버 이벤트), 테스트 질문·보고 = 모든 것 검수.
