# 인기 로블록스 RPG의 UI 조사 + 우리 UI 고칠 점 (2026-10-12)

사용자 요청: "유튜브에서 로블록스 RPG들이 UI를 어떻게 하는지, 캐릭터 정보창까지 보고 우리 걸 더 낫게 만들어."
이 문서는 `docs/design/ref_untitled_rpg_2026-10-12.md`('UI 비교')의 다음 조사예요. 출시 가이드 대조표(`launch_guide_check_2026-10-12.md` 1번)가 "인기 RPG 2~3개 더"를 하라고 했어요.
코드·`src/`·`tools/`는 건드리지 않았고 커밋도 하지 않았어요. 읽기만 했어요.

## 방법과 한계 (솔직하게)

- 본 게임 6개: **Blox Fruits, King Legacy, Swordburst 3, World // Zero, Arcane Odyssey, Dungeon Quest Reborn**. 예전 조사(UNTITLED RPG GAME)는 그 문서를 그대로 가져왔어요. Grand Piece Online은 제목·챕터만 봤고 화면은 못 봤어요.
- 영상은 **소리 끄고 멈춘 화면만** 봤어요(내장 브라우저, 음소거 + 일시정지). 로그인·좋아요·댓글은 안 했어요.
- **자막은 못 받았어요.** YouTube가 자막 요청을 막았어요(HTTP 429, 몇 번 다시 해도 같았어요). 그래서 `[자막]` 표시는 이 문서에 없어요. 대신 **제목·설명·챕터**와 **화면에 박힌 글자(영상 편집 자막 포함)**로 읽었어요.
- 화면 사진 28장은 `build/ref/rpg_ui/`에 있어요(git 무시 폴더, 커밋 안 함). 파일 이름에 게임 약자·영상 id·초가 들어 있어요. `info_<영상id>.json`은 제목·설명·챕터 보관본이에요.
- 영상 연도가 달라서 **지금 화면과 다를 수 있어요**: King Legacy 일부 2021~2022, World // Zero 2020·2024·2025, Swordburst 3는 2023 알파, 나머지는 2025~2026.
- 못 본 것: 댓글, 폰 화면(Blox Fruits 영상 1개뿐), 장비 비교 화살표(아래 표 7번), 세트 보너스.
- 글 단어 수는 화면에서 눈으로 센 대략 값이에요 `[추측]`.

표시 약속: `[화면]` 멈춘 화면에서 본 것 / `[설명]` 영상 제목·설명·챕터 / `[추측]` 내 생각(확인 못 함).
저작권: 화면은 내 말로만 적었고, 따옴표 글은 하나(King Legacy 영상 편집 자막 4단어)뿐이에요.

## 한눈에: 가장 큰 교훈 5개

1. **스탯 창은 작고 숫자 중심이에요.** Blox Fruits 5줄, King Legacy 4줄, Dungeon Quest 3칸. 줄마다 [이름 + 숫자 + [+] 버튼]이고, 아래에 "남은 점수"와 "초기화"가 늘 있어요. 설명 글이 거의 없어요. 우리 Stats 탭은 흰 글 약 20줄이라 반대예요.
2. **장비는 몸 위에 놓아요.** Swordburst 3은 몸 윤곽선 위에 장비 카드를, Dungeon Quest는 몸 둘레 동그라미 칸을, Blox Fruits 프로필은 3D 캐릭터 아래에 장비 아이콘을 놓아요. 우리는 작은 칸 6개를 격자로 놓고 창 아래 절반이 비어 있어요.
3. **내 캐릭터를 3D로 보여 줘요.** Blox Fruits 프로필 카드와 World // Zero 상점(입어 보기)이 그래요. 우리는 이미 HUD에 3D 얼굴(`HUD.luau` `L.RefreshPortrait`, ViewportFrame)이 있어서 **몸 전체로 넓히기가 쉬워요.**
4. **아이템 = 등급 색 칸 + 작은 칩(Lv, +N, 개수) + 설명 3줄 안쪽.** 우리 가방도 같은 모양이에요. 모자란 건 "내 전투력이 얼마나 바뀌나"를 **색과 화살표**로 한눈에 보여 주는 일이에요.
5. **글이 적은 창이 깨끗하고, 글이 많으면 설명 영상이 따로 필요해요.** Arcane Odyssey는 채팅·로그북·스탯이 빽빽해서 "스탯 설명" 영상만 8분이에요. 우리 A23-130(글 줄이기)과 같은 방향이에요. **새 글 대신 아이콘·숫자·색**으로 가요.

한 줄 더: 우리 쪽에서 **이미 있는 걸 몰라서 제안하면 안 되는 것**이 있어요 — 퀘스트 줄의 진행 막대·골드 보상(HUD에 이미 있음), 가방의 "Power A → B" 줄(이미 있음, 초록색 처리까지 있음), 탭의 새 항목 점(BadgeDot, 가방에 있음).

### 2. 잘 만든 창이 "먼저" 보여 주는 것 (순서)

1. **나**: 모습 + 이름 + 레벨. (Blox Fruits 프로필은 3D 모습 + 모서리 레벨, Dungeon Quest는 초상화 + 레벨 뱃지.)
2. **지금 할 수 있는 일**: "남은 점수". 창 아래 또는 위에 **늘 같은 자리**. (Blox Fruits "Available Points", King Legacy "Points", Dungeon Quest "Points Left".)
3. **숫자 3~5개**: 한눈에 다 읽히는 개수. 10개짜리(Swordburst 3)는 점수 찍기가 없는 읽기 전용이에요.
4. **장비는 몸 위**: 어디에 뭘 꼈는지가 몸 모양으로 읽혀요.
5. 나머지(통계·칭호·자랑 칸)는 **두 번째 단계**: Blox Fruits는 프로필 카드 안에 Statistics 창(Bounty·Honor·열매 9/41·스타일 1/12…)이 따로 있어요 `[화면]`.

→ 우리 Hero Gear 탭은 1번이 2D 사진, 2번이 없고(점수 시스템 꺼짐), 3번이 Stats 탭에 가려 있고, 4번이 격자예요. **순서는 맞지만 내용이 비었어요.**

### 3. 전투력 숫자 풀어 보기

- 코드로 확인한 것: `Config.PowerOf = √(무기 피해 × 공격 배수 × 기본 체력 × 체력 배수)`이고 화면 전투력은 환생 배수 없이(1) 계산해 ×10으로 보여 줘요(`Config.CombatPower`, `Config.Power.DisplayScale`). 즉 **전투력은 "공격"과 "체력" 두 숫자에서 나와요.** Stats 탭의 `Base hit`, `Max HP`가 그 재료예요.
- 게임들은 한 숫자(전투력)를 만들어 보여 주지 않고 **재료 숫자를 그대로** 보여 줘요(Swordburst 3 ATK/MAXHP, Dungeon Quest 물리·마법·체력). 우리는 반대로 **합친 숫자만 크게, 재료는 다른 탭**에 둬서 "왜 702지?"가 안 풀려요.
- 제안: Power 숫자 아래에 칩 두 개 **[칼] 공격 N · [하트] 체력 N**. 누르면 출처 3~4줄:

| 출처 | 지금 켜짐? | 칩을 누르면 |
|---|---|---|
| 레벨(기본 체력) | 켜짐 | "Level 30" |
| 무기 단계 + 주문서 +N | 켜짐 | "Dawn Sword +3" |
| 스탯 점수(공격·체력) | 꺼짐(`Features.StatPoints=false`) | 켜지면 "Points +3" |
| 방어구(체력 %)·반지(공격 %) | 꺼짐(`Features.Gear=false`) | 켜지면 "Armor +12%" |

- 규칙 확인: 환생·덩치 저울·깡패는 전투력에 안 들어가요(`Config.Power` 주석). 창에도 안 보여 주고 지금처럼 Stats 탭의 "지금 걸린 것"에만 둬요.

### 4. 비교(올라가나 내려가나)

- 본 게임에서 **초록/빨강 화살표는 못 봤어요.** 다들 숫자 줄만 보여 줘요. 그래서 우리가 **한 줄로 끝내면 더 쉬워요.**
- 우리는 이미 "Power A → B"가 있어요(좋을 때만 초록). 제안:
  - **▲ +101**(초록) / **▼ −20**(빨강) / **=**(회색) + 차이만 크게. 글자 ▲▼이 Roblox 글꼴에서 나오는지 확인하고, 안 나오면 "+101 / −20" 색만 써요 `[추측]`.
  - 자리 3곳: 가방 설명 카드, Hero 무기 목록(`CharacterUI.luau` 약 804~811줄 `PowerChange`), 드롭·장착 토스트(`Config.Text` `BareEquip`).
  - PC는 칸에 마우스를 올리면, 폰은 칸을 한 번 누르면 같은 카드.
  - 방어구·반지가 켜지면 공격/체력 차이를 따로(칸 모양이 달라서).
  - 못 쓰는 것(레벨 모자람)은 비교 대신 [From Lv 40] 잠금(지금처럼).

### 5. 3D 아바타 미리보기

- 본 곳: Blox Fruits 프로필(3D 렌더 + 레벨 모서리 + 옷 아래 장비 아이콘), World // Zero 상점(고른 탈것을 내 캐릭터가 타고 있음) `[화면]`. Swordburst 3·Dungeon Quest는 3D가 아니라 윤곽선·동그라미 칸이에요.
- 우리 재료: **`HUD.luau` `L.RefreshPortrait`가 이미 ViewportFrame + WorldModel + 캐릭터 복제로 3D 얼굴을 그려요.** Hero 창은 아직 2D 머리 사진(`UIKit.HeadshotImage`)이고, 10/09 점검에서 "초상화 빈 원"이 Studio에서 나왔어요(`ui_clutter_review_2026-10-09.md`). 3D로 바꾸면 그 문제도 같이 사라져요.
- 이미 계획이 있어요: **BB8b "장비창 3D 아바타 미리보기"**(`beta_basics_2026-10-05.md`, 권장·중간). 이 조사는 "올려도 된다"를 뒷받침해요.
- 확인할 것 `[추측]`: 무기를 쥔 자세는 `WeaponPose.luau`가 **클라이언트에서 관절에 씌우는 값**이라 복제본에는 안 보여요. `WeaponPose.Angles`(순수 함수)로 복제본에도 한 번 씌워야 해요. 무기(`WeaponModel`)와 후광/뿔(`HaloModel`/`HornsModel`)은 캐릭터에 붙어 있어 같이 복제돼요.
- 조작: 끌어서 돌리기(창 안에서만, 카메라 회전 규칙 A23-51과 별개) · 더블클릭으로 정면.

- 우리 설계(A23-69)는 이미 더 쉬워요: **스탯 2개(Attack·Health), 기본 자동 ON, 초기화 무료, 돈으로 안 팖.** 화면만 없어요(`Features.StatPoints=false`, 서버 StatService는 `dev2-stats2`에 보관, 일정상 서버 10/31~11/06, Stats 탭 11/07~11/13: `gameplay_remaining_2026-10-11.md`).
- 제안 Stats 탭 위쪽(스탯이 켜졌을 때):
  `[칼] Attack +3 [+]   [하트] Health +2 [+]   남은 점수 1   [자동 ●]   [초기화]`
  + 누르는 순간 아래에 "Power 702 → 710"이 바뀌어 보여요(Dungeon Quest의 "점수 쓸 양" 슬라이더는 **2스탯이라 필요 없음**).
- 자동 ON일 때는 [+]를 흐리게 하고 점수가 알아서 찍혀요(글 설명 없이 토글 모양으로만).

### 7. 세트 보너스

- **본 6게임에서 세트 보너스 화면은 못 봤어요.** World // Zero 무기는 퍼크 3줄, Swordburst 3은 인챈트 9가지 보너스 `[화면]`이라 "장비 한 개에 붙는 옵션"이 중심이에요. World // Zero 연출 화면의 "Zero Gear"라는 이름은 세트일 수 있지만 확인 못 했어요 `[추측]`.
- 우리 장비는 방어구·반지가 각각 3등급 × +2(`Config.Gear`)이고 무기는 주문서 +N이에요. 퍼크·세트는 **새 규칙**이라 사용자 확인이 필요하고 베타 범위도 넘어요 → **이번엔 안 해요.** (나중에 한다면 Gear 탭 아래에 "같은 등급 2/3" 칩 한 개.)

### 8. 칭호

- 우리: 진영 등급 칭호(명예/악명 5단계 `Config.Titles`) + 고른 칭호(`TitleDefs`) + Auto. Hero 오른쪽에 단추 2개, "다음 등급"은 Stats 탭 글 한 줄이에요.
- 본 곳: Arcane Odyssey Logbooks 탭 "Titles" `[화면]`. 나머지는 칭호가 창에 안 보였어요.
- 제안: 이름 아래 **칭호 리본**(승인 그림 `TitleRibbon` 있음) + **다음 등급 막대**(`BarFill`, `IconRankHonor`) + 잠긴 칭호는 회색 + 얻는 조건 숫자만(예 "Honor 50"). 목표가 보이는 건 A23-99가 남기라고 한 "보상"에 들어가요.

### 9. 다른 사람 카드 (프로필)

- Blox Fruits: "Choose a player to inspect" 목록(Server / Global 탭 + 검색) → 카드(3D 모습, 이름, 상태 줄, 마지막 접속, 쇼케이스 6칸, 통계 창) `[화면]`. Dungeon Quest 새 인벤토리 영상 설명에 "inspect ui"가 있어요 `[설명]`.
- 우리: 진영 경쟁·PvP 이야기와 잘 맞아요. 이름표를 누르면 카드(Lv·Power·직업·진영·칭호·무기, 명예/악명). **개인정보·아이 안전 확인이 먼저**라 베타 뒤로 둬요.

## 하지 말 것 (이 게임들이 하는데 우리는 피할 것)

- **스탯 점수를 돈과 엮기**: 초기화·점수·빌드 변경권을 팔지 않아요(A23-69, 능력치는 안 팖). 본 게임 3곳이 "빌드 겁주기" 구조라 더 조심해요.
- **"최고 빌드" 압박**: 한 스탯 몰아찍기 권하는 안내 문장, 빌드 영상이 필요한 구조. 우리는 자동 ON + 공짜 초기화를 유지해요.
- **스킬 버튼에 MP 숫자**(Swordburst 3·UNTITLED가 함): **A23-60 사용자 결정**으로 안 해요.
- **영어 약어 스탯**(ATK·SPREGEN·BURSTPWR 등): 아이가 몰라요. 우리는 아이콘 + 쉬운 말(Attack·Health).
- **글 빽빽한 창·채팅 로그**(Arcane Odyssey): A23-130 위반 방향. 새 창에는 글 대신 숫자·아이콘·색.
- **빛살(광선) 모양 아이템 연출**(World // Zero 새 아이템 화면): "빛살 무늬 금지" 규칙.
- **돈 늘리는 [+] 단추를 HUD·상점 위에 늘 달기**(Dungeon Quest 위쪽 돈 알약, World // Zero 수정 [+]): 베타 전에는 게임 패스·개인 서버만 판매(A23-75). 상점 안의 구매 안내는 따로 검수.
- **보상 줄이 계속 쌓이는 팝업**(Blox Fruits·King Legacy "Earned…"): 한 번에 하나(A23-130).
- **퍼크·세트 옵션을 새로 만들기**(World // Zero 퍼크 3줄, Swordburst 3 인챈트 9가지): 새 규칙·새 화면이라 사용자 확인 + 베타 범위 밖.
- **코드로 새 꾸밈 만들기**: 새 모양(프로필 카드 틀, 리본 등)은 승인된 `Config.UIArt` 부품·`UIKit` 대체만 써요. 새 그림이 필요하면 Firefly 승인 먼저(이 문서 #6만 해당).
- **노란 글자 단추만 세로로 쌓은 단순 메뉴**(Blox Fruits 왼쪽 Stats·Items·Shop·Close): 우리 6칸 메뉴 타일이 더 좋아요.
