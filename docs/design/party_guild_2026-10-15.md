# 파티·플레이어 길드 설계 — 2026-10-15

상태: 개발용 제안서. A23-201·202의 확정 규칙을 우선한다. 아래 비용·거리·기간·성장 수치는 **제안값**이며 구현 완료나 사용자 승인으로 보지 않는다. 이번 작업은 문서만 작성한다.

## 1. 파티: 먼저 출시할 최소판

| 동작 | 서버 규칙 | 화면·반응 |
|---|---|---|
| 초대 | 같은 서버의 준비 완료 플레이어. 친구 또는 가까운 플레이어(60 studs) 목록에서 초대. 이미 파티면 대장만 초대. 초대당 30초, 동일 대상 30초 간격, 보낸 사람당 동시 3개 | 플레이어 행의 기존 사람+ 아이콘. 받은 초대는 소셜 창의 아바타·이름·수락/거절 행과 메뉴 점으로 표시. 강제 설명 팝업 없음 |
| 수락 | 서버 발급 InviteId 단일 사용. 두 사람의 접속·현재 파티·대장 권한·남은 자리 재검증. 파티 없음→첫 수락 때 2명으로 생성. 자리 예약 없이 직렬 처리하여 최대 4명 | 서버 확정 뒤 프레임이 자리로 들어오고 짧은 합류음 |
| 거절·만료 | 인원·보상 변화 없음. 상대가 나가거나 대장 변경·파티 해산이면 해당 초대 무효 | 초대 행만 사라짐. 공개 거절 알림 없음 |
| 탈퇴 | 누구나 즉시 탈퇴. 대장은 가장 먼저 들어온 남은 사람에게 자동 승계. 1명만 남으면 해산. 재초대는 새 InviteId 필요 | 자신의 파티 프레임·점 제거. 남은 사람 프레임 정렬 |
| 추방 | 대장만 다른 멤버 추방. 마지막 유효 전투 참여 뒤 15초 동안 추방·수동 대장 변경 잠금. 자발적 탈퇴는 가능 | 파티 창 멤버 행에서 실행. 오조작 방지는 길게 누르기 진행 원, 새 설명 확인 창 없음 |
| 대장 넘기기 | 같은 파티 멤버에게만. 전투 잠금·현재 대장 재검증 | 기존 왕관 아이콘 이동 |
| 접속 종료·서버 이동 | 종료 즉시 탈퇴 처리. 재접속 자동 복구·다른 서버 초대/파티 연결·자동 텔레포트 없음 | 같은 서버에서 다시 초대. 기존 Roblox 친구 초대는 서버 합류 수단일 뿐 파티 수락을 대신하지 않음 |
| 진영·PvP | 혼합 진영 파티 허용 제안. PvE 협력만 제공. 진영·PvP 피아 판정·도시 입장·장인 비전투 규칙 불변 | PvP에서 위치 노출 금지. 파티·길드 가입으로 적 위치를 추적하거나 아군 보호 규칙을 우회하지 못함 |

### 1-2. 퀘스트 인정: 처치 보상 이벤트와 분리

`PartyService`와 `QuestCreditService` 신설. 서버의 검증된 **실제 HP 감소** 지점에서만 기록하고, 몬스터 생명마다 고유 SpawnId를 쓴다. 클라가 hit 수·PartyId·피해량·퀘스트 수령자를 정하지 못한다.

| 기록·판정 | 제안 계약 |
|---|---|
| 참여 장부 | `Participation[SpawnId][UserId]={FirstHitAt,LastHitAt,DistinctHitTimes,PartyId,MembershipEpoch,PartySnapshot}`. PartySnapshot은 그 타격 때 멤버별 UserId+가입 epoch. 유효 거리·시야·생존·피해 검증을 통과한 공격만. 펫은 소유자에게 귀속 |
| 일반 참여자 집합 H | 사망 시 같은 서버·같은 구역, 몬스터에서 80 studs 안, 마지막 실제 타격이 15초 이내. 타격 때도 각 공격 고유 사거리 검증. 첫 타격자 ID는 별도로 보존 |
| 보스 H | **최종 검수 10/15 d: 보스 보상을 받는 사람 전원**(보상 자격과 같게, 15초·80 studs 조건 없음 — 물약·부활 중이어도). 파티 보스 왕관(PartyBoss)만 서로 다른 시전/기본 공격에서 **3초 이상**(10/15 b, `Config.Party.BossHitGap`) 간격의 실제 타격 2회 필요. 지속 피해 여러 tick·다중 투사체 한 시전을 2회로 세지 않음 |
| 합동 퀘스트·모든 보스 목표 | H 전원 각자 +1. 파티 보스 왕관 풀은 참가자 진영마다 한 번(10/15 c, 첫 타격자 진영 두 배 X). 파티 여부 불문. 보스 목표는 개인 퀘스트에 들어 있어도 보스 참여 규칙 우선. 안 때린 파티원에게 보스 진행 없음 |
| 개인 일반 처치: 파티 없음 | 첫 타격자가 H에 있을 때 그 사람만 +1. 나중에 때린 비파티 사람은 0. 첫 타격자가 이탈했다고 다른 비파티 사람에게 넘기지 않음 |
| 개인 일반 처치: 파티 있음 | H의 각 공격자를 기준으로 **그 공격자의 실제 타격 당시와 사망 순간에 같은 파티·같은 가입 epoch였던 사람**까지 인정. 그 파티가 첫 타격자가 아니어도 해당 참여 파티는 인정. 마지막 순간 초대는 소급 인정 안 함 |
| 안 때린 파티원의 최소 조건 | 같은 구역·80 studs·접속 유지, 생존 또는 그 전투에서 KO, 최근 30초 내 서버가 확인한 이동/공격/스킬/부활 등 활동. 마을·AFK·다른 서버에서는 0. 일반 개인 처치에서만 적용하는 제안 |
| KO 처리 | 직접 때린 뒤 그 전투에서 KO된 사람도 시간·거리 조건을 만족하면 인정. 마을 부활로 거리 밖이면 제외. 추방으로 기여를 지우지 않음: 파티를 나간 직접 공격자는 해당 퀘스트의 비파티/합동 규칙으로 판정 |
| 각 수령자의 조건 | 실제 활성 퀘스트·현재 단계·목표 종류·레벨/지역 조건 검사. 참여 전에 활성화된 단계만. `SpawnId+UserId+QuestId+Step` 중복 제거, 수령자 집합 합집합으로 한 번만 |
| 공유하지 않는 행동 | NPC 대화·아이템 줍기/사용·스킬 시전 과제·제작·출석·선악 선택은 본인이 수행. 개인 퀘스트의 **처치 목표**만 파티 공유. `SkillMulti`, `FarKills`, `BasicKills` 직업 숙련 과제·왕관 조각 개인 시험은 대리 수행 불가 제안 |
| 기존 보상 유지 | XP·골드·드롭·도감·TotalKills·HuntFame·왕관 점수·거위 특수 보상은 이 API로 지급하지 않음. `MonsterKilled`를 사람 수만큼 재발행하지 않고 기존 퀘스트 구독만 새 진행 API로 연결 |

개발 2는 모든 처치 목표에 `CreditMode=PersonalKill/SharedKill/BossParticipation/SelfAction`을 명시한다. 미분류 목표는 기존 동작으로 두고 목록을 검수한다. 새 퀘스트도 명시 없이는 공유하지 않는다.

현재 `MonsterService.DamageMonster`와 `_contributors/_hits/_dmg/_share`를 연결 지점으로 삼되, 기존 보상용 기여 기준을 퀘스트 기준으로 덮지 않는다. 사망 때 장부를 지우기 **전** 퀘스트 전용 스냅샷을 만들고 `QuestService`·`StoryQuestService`의 해당 처치 진행 구독을 이전한다. 개인 전용/조용한 시험 몬스터는 기존 소유자 제한·보상 제외를 유지한다. 기록은 몬스터 리셋/소멸 시 정리, 보스 유효 타격 시각은 필요한 두 개만 보관하며 중복 처치 표도 서버 내 제한 크기·수명으로 관리한다.

| 필수 사례 | 기대 결과 |
|---|---|
| A 첫 타격, B 후속 타격, 둘 다 비파티 | 개인 일반 처치 A만, 합동은 A·B |
| A 비파티 첫 타격, B·C 같은 파티, B 타격·C 근처 활동 | 개인 일반 처치 A·B·C. C가 멀거나 AFK면 A·B |
| A·B 파티, A만 보스 타격 | A가 보스 보상을 받으면 A만. B 0 |
| 공격 뒤 가입/탈퇴 후 재가입 | 새 epoch에 옛 공격을 붙이지 않음 |
| 동일 죽음 콜백 2회, 파티 공격자 3명 | 해당 단계 진행은 사람별 1회 |

## 2. 플레이어 길드: 이름·가입·운영

| 항목 | 제안 |
|---|---|
| 화면 이름 | **Adventure Club / 모험단**. 메뉴는 `Club / 모험단`, 화폐 `Club Coins / 모험단 코인`. 내부 모듈·저장 이름은 Guild. 진영 `Artisan Guild / 장인 길드`는 변경하지 않음 |
| 이름 | 3~20자, 공백 정리·제어문자/링크 금지. 같은 표시 이름 허용, 구별은 서버 발급 8자리 영숫자 코드. 검색 결과는 이름+코드+대장 이름. 코드 충돌은 DataStore 예약 후 재생성 |
| 만들기 | Lv10·총 플레이 60분·계정 7일 이상, 2,000골드 1회. 주머니→은행 순서, 완성 실패는 서버 복구. 한 계정 한 길드, 창설자는 Leader. 이름만 미리 점유하고 돈을 반복 받지 않음 |
| 가입 | Lv5부터 무료, 진영 혼합 가능. 가입 자체에 계정 나이 제한 없음. 초대 또는 코드로 가입 신청. 자동 가입은 베타 제외 |
| 정원 | Lv1~4 12명 → Lv5~7 16명 → Lv8~10 20명. 접속 인원이 아니라 전체 멤버 수. 모든 활성 가입·가입 예약이 정원에 포함 |
| Leader | 1명. 초대/승인, 일반 멤버 추방, Officer 임명·해임(최대 2명), 대장 이전. 기부금 인출·남의 코인 사용 불가 |
| Officer | 최대 2명. 초대/신청 승인, Member만 추방. Leader/다른 Officer 추방·직급 변경 불가 |
| Member | 출석·기부·상점·탈퇴. 역할별 전투/XP/화폐 배수 없음 |

## 3. 출석·기부·성장 경제

### 3-1. 매일 할 수 있는 일

| 행동 | 골드 비용 | 길드 XP | 개인 코인 | 제한 |
|---|---:|---:|---:|---|
| 출석 버튼 | 0 | 50 | 0 | KST 하루 1회, 자동 접속 지급 아님 |
| 오늘 1번째 기부 | 200 | 20 | **100** | 출석 완료 후 |
| 오늘 2번째 기부 | 500 | 30 | **100** | 1번째 완료 후 |
| 오늘 3번째 기부 | 1,000 | 50 | **100** | 2번째 완료 후 |
| 하루 합계 | 1,700 | 150 | **300** | 계정 전체·모든 서버/길드 합산 |

사다리는 선택 메뉴가 아니라 순서다. 200골드 기부를 무제한 반복할 수 없다. 매일 1번째 비용으로 돌아가며, 마을 기금의 **평생** 사다리와 다르다. 한 번만 기부해도 100코인을 얻는다. 기부액·XP·코인·상한에는 VIP/2배 골드/XP 패스를 적용하지 않는다. 기존 골드 패스로 비용 마련 시간이 짧아질 수는 있으므로 일일 코인 상한은 모두 같다.

| 안전·운영 | 규칙 |
|---|---|
| 기여 자격 | 가입 24시간·계정 7일·총 플레이 60분 이후 출석/기부/구매 허용. 새 계정도 멤버로 어울릴 수 있음. 기존 개인 출석은 그대로 사용 |
| 빠진 날 | 연속 출석 보너스·벌점·길드 XP 하락·놓친 날 결제 복구 없음 |
| 상한 | 코인 지갑 99,900, 훈련 재료 999. 100을 온전히 받을 공간이 없으면 **차감 전 기부 차단**. 기부 1회=정확히 100 보존 |
| 부계정 | 기부/코인/재료/책 양도 불가, 가입 보너스 없음, 전역 일일 횟수·가입 대기·정원으로 반복 수확 억제. 계정 나이만으로 부계정 판별 가능하다고 주장하지 않음; IP/기기 개인정보 수집 없음 |
| 운영 기록 | 계정별 기부·XP·코인 발행/소비·중복 요청·복구 건수, 길드당 활동 인원·Lv2/4/7/10 도달 시간 기록. 공개 기부 순위·기부 강요 알림 없음 |

### 3-2. 베타 길드 Lv1~10

다음 레벨 필요 XP는 현재 레벨 L에서 `500 × (L+1)`(L=1..9). 누적 XP로 레벨을 계산하고 감소하지 않는다. Lv10의 성장 XP는 27,000으로 고정하되 출석·기부·코인 지급은 계속된다.

| 1 | 1,000 | 0 | 출석·기부, 12명 |
| 2 | 1,500 | 1,000 | 길드 상점·훈련 쪽지, 스킬 Lv2 |
| 3 | 2,000 | 2,500 | 스킬 Lv3 |
| 4 | 2,500 | 4,500 | 첫 교체 스킬북(Q) |
| 5 | 3,000 | 7,000 | 정원 16명 |
| 6 | 3,500 | 10,000 | 스킬 Lv4 |
| 7 | 4,000 | 13,500 | 두 번째 교체 스킬북(Z) |
| 8 | 4,500 | 17,500 | 정원 20명 |
| 9 | 5,000 | 22,000 | 스킬 Lv5 |
| 10 | — | 27,000 | 모험단 명단의 완성 배지(기존 별 아이콘), 추가 전투 보너스 없음 |

속도 예시(가입 대기 종료 뒤): 8명이 출석+3회 기부하면 1,200XP/일 → Lv10 약 23일, 출석+1회만 하면 560XP/일 → 약 49일. 12명이 풀 기여하면 1,800XP/일 → 15일. 멤버가 늘면 더 빨라진다. 이는 계산값이며 실제 재화 수급 검증값은 아니다.

### 4-1. 상점 품목과 스킬 Lv1~5

|---:|---:|---:|---:|---:|

누적 26장=2,600코인/스킬. Q·Z·X와 교체 스킬 각각 독립 Lv. 피해는 최종 스킬 피해에 한 번만, 지속 피해는 tick에 한 번만 적용. 사거리·범위·대상 수·MP·치유·흡혈·방어율·이동거리·군중제어 시간은 증가하지 않는다. 피해로부터 계산하는 치유/흡혈도 강화 전 피해를 기준으로 하여 간접 증가를 막는다. 예: Q 기본 CD3초 → Lv5 2.88초, 기본 피해60 → 64.8을 기존 반올림 경로에서 처리.

베타 제안: 강화 효과와 교체 스킬은 PvE에만 적용. PvP/왕관전은 원래 기본 스킬 Lv1 성능·기존 `PvPZX` 제한. PvP 진입 시 서버가 기본 variant로 계산하고 UI도 일치시킨다. 탈퇴·환생·직업 변경으로 책/강화 기록을 지우지 않으며, 다른 직업 스킬은 저장만 하고 사용할 수 없다.

### 4-2. 새 스킬북의 의미

새 스킬북은 추가 버튼이나 상위 필수 스킬이 아니라 **같은 슬롯의 다른 전투 방식**을 영구 배우는 책이다. 베타는 표시 직업마다 Q 대안 1개+Z 대안 1개, 총 18개 이름/외형·6개 기본 동작 유형으로 한다. X는 기본 스킬만 두되 저장/선택 구조는 Q/Z/X 모두 지원한다. 기본 스킬은 스승에게 무료로 배우는 현재 경로 그대로다.

| 단계 | 계약 |
|---|---|
| 구매 | 현재 kit·슬롯 학습·길드 해금·자격·중복·가격을 서버 검사. 책은 전용 귀속 보관함에 1권, 일반 가방/Market에 넣지 않음 |
| 배우기 | 현재 진영 스승에게 거리16 안에서 책 사용 → 책 소비+variant 영구 등록+Lv1 저장. 슬롯 레벨·Tasks·Learn·Z/X 전역 스위치를 우회하지 않음 |
| 장착 | 스승 근처·비전투 10초에서 기본/대안 선택. 동시에 슬롯당 1개. 교체 전 남은 CD와 새 기본 CD 중 긴 것을 적용, 교체/재접속으로 CD 초기화 금지 |
| 사용 | 같은 MP·재사용·서버 타격 검증·0.35초 입력 버퍼·허공 시전 규칙. 자동 공격은 기존 해금 뒤 허용된 variant만, 몬스터만. 공중 시전·자동 사용은 숙련 과제를 부풀리지 않음 |
| 저장 단위 | `Kit.Slot.Variant`의 안정 ID. Halo/Horns 이름은 같은 ID의 진영 표현만 달라져 중복 구매하지 않음. Neutral kit는 별도. 기존 기본형은 `Base` |

|---|---|---|---|

| 코드 예약 | 같은 store의 `C_<8자리코드>={GuildId,CreateOpId,State}` | UpdateAsync로 비어 있을 때만 예약. 표시 이름 중복은 허용. 생성 재시도는 같은 OpId로 복구 |
| 현재 접속 | MemoryStore SortedMap `HHGuildLive_<guid>`, uid → `{JobId,SessionToken,At}`, 30초 갱신·90초 TTL | 온라인 숫자/같은 서버 표시의 힌트. 만료 시 자동 제거, 실패면 `—`; 권한·코인·일일 상한 판정에 사용 안 함 |
| 갱신 알림 | MessagingService에 GuildId+Revision만, 해당 길드 접속 서버에 구독. 알림 누락 대비 활성 길드 60초 재조회 | 클라는 최신 revision만 적용. 다른 서버에서 추방된 멤버의 새 기부/구매는 영구 장부 재검증으로 즉시 차단 |

Roblox `UpdateAsync`는 같은 키의 서버 간 변경 충돌을 처리하며 callback이 재실행될 수 있다. callback 안에서 골드 차감·원격 전송·다른 저장·yield를 하지 않는다. **플레이어 키와 길드 키를 한 번에 원자적으로 저장해 주지는 않는다.** MemoryStore는 임시 데이터이므로 영구 장부를 대체하지 않는다. [공식 DataStore](https://create.roblox.com/docs/cloud-services/data-stores), [UpdateAsync](https://create.roblox.com/docs/reference/engine/classes/GlobalDataStore), [MemoryStore](https://create.roblox.com/docs/cloud-services/memory-stores).

### 5-2. 기부 처리: 영구 예약 → 길드 반영 → 개인 확정

| 순서 | 서버 처리·중단 복구 |
|---|---|
| 1. 검증·예약 | 계정별 mutation mutex. 한 번에 미완료 작업 1개. 서버가 `Seq`, `OpId=uid:Seq`, GuildId, MembershipEpoch, KST Day, Tier, Gold, XP, Coin100을 확정. 해당 골드를 가용 잔액에서 빼고 `Guild.Pending`과 같은 프로필 저장에 넣음. 일일 슬롯도 예약 |
| 2. 저장 확인 | 기존 DataService 세션 토큰·직렬 저장 경로로 **영구 예약 성공 확인** 후에만 길드에 보냄. 응답 불명은 새 OpId 생성/성공 표시/무조건 원복 없이 같은 예약 재확인. 예약 저장 전엔 길드 XP 0 |
| 3. 길드 UpdateAsync | 현재 멤버 epoch·자격·Closed·Seq 검사. 새로운 Seq면 XP를 더하고 `LastSeq/LastResult={OpId,Committed,XP,Day}`를 함께 저장. 같은 Seq 재시도는 기존 결과만 반환. 더 낮은 Seq는 거부 |
| 4. 개인 확정 | Committed 영수증을 확인하면 예약→사용 완료, 코인 정확히+100, 일일 횟수+1, Pending 제거를 **동일 프로필 저장**으로 확정. 저장 완료 뒤 성공 Fx. 이 단계 실패 시 Pending으로 3번 결과를 다시 읽고 한 번만 마무리 |
| 5. 확정 거부 | 미가입/해산 등 `Rejected` 결과가 영구 기록되었을 때만 예약 골드·일일 슬롯을 정확히 원복. 네트워크 timeout은 거부가 아니므로 환원하지 않고 재시도. 복구 금액에 골드 패스 배수 금지 |
| 6. 재접속·종료 | PlayerReady에서 Pending 정산을 일반 조작보다 먼저. 서버 종료 때 가능한 저장을 시도하되 BindToClose만 믿지 않음. 계속 실패하면 해당 경제 동작만 잠그고 영구 Pending 유지 |

기부 직후 자정이 지나도 예약의 Day·Tier로 처리한다. 미완료 작업을 정산한 뒤 오늘 날짜로 횟수를 바꾼다. `LastResult`를 덮기 전에 이전 개인 확정이 끝났음을 확인한다. 남의 서버가 가진 프로필을 캐시 복사로 쓰면 안 된다.

| 다른 충돌 | 같은 원칙의 처리 |
|---|---|
| 출석 | 계정의 Day 예약 → 길드 XP50 한 번 → 출석 완료. 기존 개인 출석 기록/보상은 재지급하지 않음 |
| 추방·탈퇴 중 기부 | 멤버를 지우기 전에 epoch·마지막 영수증을 `Departures`에 보존. 기여가 먼저 확정됐으면 코인 지급, 탈퇴가 먼저 확정됐으면 거부·골드 복구. 개인 정산 ACK 전 영수증 제거 금지 |
| 오래된 요청 재전송 | 탈퇴 후 새 가입은 새로운 epoch. 이전 epoch는 다시 활성 멤버로 인정 안 함. 완료 확인된 departure 정리는 가능하지만 미정산 항목은 시간만으로 삭제하지 않음. 저장 크기 임계 전 새 가입/거래를 차단하고 복구 |
| 가입 경쟁 | 수락자의 잠긴 프로필에 가입 Pending 1개 → 길드 UpdateAsync에서 정원 예약 → 프로필 포인터 확정 → 길드 Active 확정. pending도 정원 포함. 실패는 같은 OpId로 완료/취소; 활성화 전 출석/기부/구매 불가 |
| 창설 경쟁 | 창설 골드 예약 → 코드 예약 → 길드+창설자 Pending 생성 → 프로필 소속 확정 → Active. 임의 TTL만으로 예약 삭제하지 않고 CreateOpId로 복구. 한 계정이 두 길드 Leader가 되는 경로 금지 |
| 구매 | 계정 Pending 구매 Seq + guild epoch/해금 확인 영수증 → 동일 프로필에서 코인 차감+품목 지급+완료 한 번. 구매 승인 뒤 추방되면 승인된 구매는 완료. 승인 전 추방이면 거부 |
| 스킬 강화/책 사용 | 재료/책 차감+스킬 레벨/학습 기록은 한 프로필 mutation과 저장. 동시 두 번 요청은 같은 request token 재응답 또는 최신 상태로 거부. 실패 시 성공 연출 없음 |
| 저장 장애·시험 | pcall+제한된 지수 재시도·쓰기 예산·rate limit. 영구 저장 불능에서는 길드 경제를 닫음. Studio 메모리 대체 모드로 실제 길드 장부를 건드리지 않음; 별도 테스트 store 사용 |

## 6. 저장 형식과 마이그레이션

길드 핵심을 배포할 때 **v6 → v7** 제안. Party만 배포할 때는 버전 변경 없음. 실제 병합 시 다른 기능이 먼저 버전을 올렸으면 최신 번호 다음을 사용한다. StoreName/KeyPrefix를 바꿔 새 계정처럼 만들지 않는다.

| v7 개인 필드 | 기본값·의미 |
|---|---|
| `Guild` | `{Id="",Epoch="",JoinedAt=0,RejoinAt=0,Coins=0,Day=0,CheckIn=false,Donations=0,Seq=0,Pending=nil}`. 탈퇴해도 Coins/Day/횟수/Seq 유지 |
| `GuildInventory` | `{TrainingPage=0,Books={}}`, Books는 안정 skill ID→1. 일반 `Items`와 분리해서 기존 가방/Market 정리기에 소실되지 않음 |

| 기본 스킬 | 기존 학습된 슬롯은 Base Lv1로 간주(기록이 없으면 lazy 생성). 새 슬롯 자동 학습 없음. 기존 스승·과제·환생 예외를 동일하게 호출 |

## 7. 개발 분할과 출시 합격선
