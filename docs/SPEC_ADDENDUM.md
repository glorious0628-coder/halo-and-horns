## A23. 사용자 결정 2026-10-05: 자동 전투 켜기/끄기·왕관 조각 선택 퀘스트·치비 코스튬 제거·대장간 계약·Firefly (최신 우선 계약)

이 절은 A22의 "자동 공격 없음"과 A1–A21·TECH_SPEC·GDD의 충돌하는 옛 내용보다 우선한다. A22의 수동 입력·MP 스킬·충전 폐기 계약은 그대로 유지한다. 작업 순서는 **게임성 먼저**다(`RELEASE_PLAN.md` 상단).

### A23-1. 수동 + 자동 전투 켜기/끄기
- **기본은 수동**: A22 입력 계약 그대로(입력1회 = 공격1회, 드래그는 카메라, 스킬은 MP20·재사용3초).
- **자동 전투 해금**: 선택 퀘스트 "내 싸움을 배우는 왕관 조각"(A23-2)을 끝내면 영구 해금된다. 진영·직업 선택 직후부터 받을 수 있고 레벨 조건은 없다. 해금 여부와 켜기/끄기 상태는 저장한다(예: `AutoCombatUnlocked`, `AutoCombatEnabled`; 기본 false). 처음 상태는 **꺼짐**.
- **자동일 때 하는 일**: 서버가 주기적으로 기본 공격과 기본 스킬을 대신 실행한다. 직업별 공격 간격·MP·재사용 시간·사거리·대상 수 규칙은 수동과 똑같이 서버가 적용한다. 스킬은 MP가 충분하고 재사용 시간이 끝났으며 사거리 안에 몬스터가 있을 때만 자동 사용한다.
- **몬스터만**: 자동 공격·자동 스킬은 몬스터(황금 거위 포함 여부는 기존 거위 규칙의 "직접 3번 이상 때린 사람만 보상"을 유지)만 때린다. 플레이어·괴수(별5 수배범 괴수화 포함)는 수동 입력으로만 때린다. 빛의 기사단 스킬의 동료 치유는 자동 스킬에서도 동작해도 된다(공격이 아님).
- **서버 검증**: 켜기 요청은 해금된 플레이어만, 준비·직업 선택·생존 상태에서만 받는다. 호출 간격 제한. 사망·리스폰·직업/진영 변경 때 자동 루프는 멈췄다가 살아 있을 때 저장된 상태로 다시 돈다. 기존 `SetAutoAttack` 원격·`AutoAttack` 속성 이름을 재사용해도 된다. 옛 HEAD(`9f71510`)의 자동 루프 코드는 참고만 하고 **충전·PERFECT·스택 계산은 되살리지 않는다**.
- **퀘스트 집계**: 처치 수 퀘스트는 자동 처치도 센다. **스킬 사용 퀘스트는 몬스터를 1마리 이상 맞힌 스킬만 센다**(사용자 확정, 마을 허공 스킬로 일일 보상 받는 문제 차단). 자동으로 쓴 스킬은 스킬 사용 퀘스트에 세지 않는다(기존 코드 동작 유지, 플레이 후 조정 가능).
- **화면**: 해금 전에는 자동 버튼을 보이지 않거나 잠금 표시로 둔다("다음 해금" 예고 문구는 쓰지 않는다). 해금 후 HUD에 켜기/끄기 버튼(PC 키 1개 + 폰 버튼). 기존 승인 UI 부품 또는 UIKit 코드 대체 그림만 쓰고 새 그림은 만들지 않는다(최종 그림은 나중에 Firefly).
- **안전**: 자동 상태로 자리를 비워도 PvP는 일어나지 않는다. Roblox 기본 무입력 퇴장은 그대로 둔다.

### A23-2. 선택 퀘스트 "내 싸움을 배우는 왕관 조각" (사용자 선택 A안)
- **위치**: 첫 임무와 별개인 **선택** 퀘스트. 하지 않아도 진행이 막히지 않는다. 진영·직업 선택 직후 퀘스트 목록에 선택 항목으로 나타나며, 첫 임무와 같은 말랑 초원에서 함께 할 수 있다. 첫 임무 진행과 겹쳐 세도 된다.
- **이야기**: 큰 슬라임이 왕관 조각을 삼켰다. 조각을 되찾으면 조각이 "네가 싸우는 법을 보여 줘"라고 말하고 내 싸움을 지켜본다. 다 배운 조각은 나 대신 싸울 수 있다(= 자동 전투).
- **단계(서버 판정)**:
  1. 말랑 초원의 **큰 슬라임 처치** → 왕관 조각 획득(퀘스트 진행 상태로만 저장, 인벤토리 아이템 아님).
  2. 조각이 지켜보는 시험 3개(순서 무관): ① **기본 공격만으로 슬라임 3마리 처치**(그 몬스터에 스킬 피해가 들어가지 않은 처치) ② **스킬 한 번에 몬스터 2마리 이상 맞히기** ③ **큰 슬라임을 체력 50% 이상 유지하며 처치**(그 큰 슬라임에 첫 타격부터 처치까지 내 체력이 한 번도 50% 아래로 내려가지 않음; 추적이 과하면 처치 순간 50% 이상으로 단순화하고 사용자에게 알린다).
  3. **선택**: 조각을 **정화**(천사 쪽) 또는 **삼킴**(악마 쪽). 어느 쪽이든 자동 전투가 해금된다. 선택은 저장한다(예: `ShardChoice = "Purify" | "Devour"`). 빛/뿔 진영은 정화 → 명예(`Honor`) 소량, 삼킴 → 악명(`Infamy`) 소량을 얻는다(값은 Config, 작게). 장인 길드는 선악 점수가 없는 진영이므로 선택과 대사만 기록하고 점수는 주지 않는다.
- **목표 시간**: 5~7분. 대사는 짧게(조각 대사 1~2줄씩), 기존 Panels/토스트/퀘스트 줄만 사용.
- **보상**: 자동 전투 해금 + 선택에 따른 명예/악명 소량. 골드·경험치 추가는 기본 없음(필요하면 사용자 확인).
- **검증**: 중복 완료·중복 보상 0, 재접속 후 단계 유지, 선택 퀘스트를 안 해도 첫 임무·대장간·일일 퀘스트가 정상.

### A23-3. 첫 임무 보상과 다음 목표
- 안내자 3쪽 대화의 **수락("함께할게요") 버튼은 첫 쪽부터** 보인다(사용자 확정 2026-10-05). "다음"으로 끝까지 읽을 수도 있다. 닫기는 여전히 수락이 아니다. 창 제목은 퀘스트 이름이 보이게(예: "안내자 · 보급로 되찾기").
- 안내 사슬이 끝나 다음 목표 줄이 사라질 때는 한 번만 "안내는 여기까지! 이제 사냥하며 강해져요" 같은 토스트로 알린다.
- 첫 임무 보상은 **150골드**(사용자 확정, 120에서 올림). 나무 무기를 바로 살 수 있지만 구매는 강요하지 않는다. 경험치 보상은 그대로 0(필요하면 사용자 확인).
  - (2026-10-06, c6d31ec 안전망) 5/5 뒤 받기를 누르지 않으면 이 서버가 5/5를 처음 본 때부터 `Config.Tutorial.AutoClaimSeconds`(60)초 뒤 150골드를 자동으로 준다(Text.AutoClaimed 알림, 받기가 먼저면 그쪽, 한 번만, 재접속하면 60초 다시). 고정 줄 본문을 눌러도 받기와 같은 길로 지급한다(이동 창·초원 빔은 5마리 전에만).
- 대장간 방문 뒤에도 **다음 목표 1줄을 고정 표시**한다. 기존 상태로만 계산하고 새 보상을 만들지 않는다. 예: Lv5 전 → "Lv5 달성 · 대장간에 철 무기가 열려요", Lv5 이상·철 무기 미보유 → "철 무기 800골드 · 보유 N골드", 그다음 → "Lv10 · 고블린 숲이 열려요". 선택 퀘스트가 남아 있으면 함께 보여 준다.
- 첫 임무를 받기 전·진행 중에는 일일 퀘스트가 첫 임무 줄을 가리지 않게 한다(폰 한 줄 표시 포함).

### A23-4. 대장간 계약(누락돼 있던 공개 계약을 기록)
- `UpgradeWeapon(tier)`: tier 1..`MaxSoldTier`(현재3). 미보유는 레벨·골드 확인 후 구매+장착, 보유는 무료 재장착, tier1은 재장착만. `SellWeapon(tier)`: tier 2..`MaxSoldTier`, 보유한 것만, `floor(가격×0.1)` 지급, 보유 비트 삭제, 장착 중이면 tier1로. `WeaponOwnedMask`: tier N = 비트 N-1, 시작 무기 비트는 항상 켜짐. `BlacksmithVisited`: 서버가 확인한 모루/상인 상호작용(구매·판매 포함)으로만 true. 거리12stud·생존·직업 선택을 서버가 확인한다. 골드는 주머니 먼저, 그다음 은행에서 쓴다.
- **환생**: ~~GDD §9대로 무기도 초기화한다 → `WeaponTier = 1`과 함께 `WeaponOwnedMask = 1`.~~ → **A23-14로 대체**: 환생은 레벨만 초기화하고 무기·골드는 유지한다.
- 기존 세이브의 tier4+ 무기는 보유 비트로 남기고 무료 재장착만 허용한다(판매 불가).
- TECH_SPEC의 "업그레이드 버튼 한 번 → 다음 티어 자동 장착" 계약은 이 절로 대체한다.

### A23-5. 치비 3D 직업 코스튬 제거
- 모든 치비 3D 직업 코스튬(A15·A17·A19 일부·A20 플레이어 표정)을 게임에서 뺀다. 플레이어는 **본인 Roblox 아바타**(R15·R6) + 직업 무기 + 헤일로/뿔로 보인다. 로블록스 스타일 직업 옷은 나중에 별도로 만든다.
- 안전한 순서: ① `Config.Costumes.Enabled = false`를 추가하고 `CostumeService`의 코스튬 선택이 nil을 돌려주게 해 모두 본인 아바타로 스폰 ② B 메뉴 "직업 코스튬" 버튼과 문구 제거 ③ 실제 Studio에서 R15·R6 아바타의 걷기·점프·공격·스킬·무기 부착·사망/부활·HUD 3D 프로필 확인 ④ 확인 후 원하면 `CostumeService`·`SkinRetargetClient`·`SkinBindingContract`·`ExpressionSkinContract`(와 플레이어용 표정)를 **Main/ClientMain 목록과 모든 require에서 먼저 뺀 뒤** 삭제 ⑤ ServerStorage의 `Costume*` 폴더 삭제는 Studio Edit에서 하고 저장·복사한다(이전 버전은 git 기록에 남고 GLB 원본은 디스크에 보관).
- `MapBuilder`가 `CostumeService`를 파일 맨 위에서 require하고, 물약 상인 NPC가 `Costume_HaloWarriorM`을 복제한다. 둘 다 먼저 바꾼다.
- 게임 속 표정(A20)은 플레이어에게 더 이상 적용되지 않는다. 몬스터 표정은 후속.

### A23-6. 상점 NPC 임시 외형
- 물약 상인·장비 상인은 우선 **기본 Roblox 스타일 NPC**(HumanoidDescription으로 만든 일반 R15, 새 그림 없음)로 세워 상점을 작동시킨다. 최종 외형은 나중에 Firefly 그림 승인 후 교체한다. 승인된 장비 상인 C 원화는 치비 스타일이라 로블록스 스타일 재그림 대상이다.
- 물약 상인 활성화(`MerchantEnabled = true`)는 구매 화면·가격·수량이 실제로 동작할 때만 한다. 가격은 사용자 확인 전까지 임시값임을 표시한다. 그 전까지 "물약을 사세요" 같은 안내는 띄우지 않는다.

### A23-7. 그림 제작 도구 변경
- 이미지 생성은 **Adobe Firefly**다(Codex/GPT 구독 해지, 2026-10-05). Firefly 웹이 Claude와 연동돼 있어 작업 세션이 브라우저로 생성한다. A14-3 등 "GPT(Codex)로 생성" 문구는 이 절로 대체한다. 승인 절차(한 장씩 보여 주기 → 사용자 선택 → 그대로 구현), 누끼·확대 검사, 단정한 옷차림, 업로드 10장 이하 규칙은 그대로다. 상세 절차는 `AGENTS.md` "Art workflow".
- **옛 그림 전부 폐기(사용자 2026-10-05):** 게임에서 안 쓰는 옛 그림(후보·거절·치비 원본·`art/out/v1`·노출 사본·옛 GPT 출력)은 바로 삭제한다. 게임에 쓰이는 그림(Config.UIArt·MaterialService의 활성 ID)은 Firefly 새 그림이 승인·적용될 때 하나씩 지운다. 범위는 UI·아이콘·캐릭터/NPC/안내자·글자 그림·**바닥 지형 텍스처15개**. 3D 몬스터 모델은 제외. 게임성 단계가 끝나면 바로 시작한다(진영 화면 → HUD·공통 화면 → 아이콘 → 캐릭터·NPC → 지형). 새 그림은 글자 없는 빈 판을 기본으로 하고 글자는 게임 안 TextLabel로 넣는다(한영 전환). 지형은 이어 붙여도 이음새 없는 정사각 타일.

### A23-9. 진영 선택 전 3D 오프닝 (사용자 선택 A안, 2026-10-05)
- 진영을 아직 안 고른 플레이어의 첫 접속에 **15~25초 3D 연출**을 보여 준 뒤 FactionPicker를 연다. 이미 진영이 있는 플레이어는 보지 않는다. 본 기록은 저장한다(예: `IntroSeen`). 메뉴에 "오프닝 다시 보기".
- 장면(사용자 확정: 교차로 하늘의 왕관 사용, `왕관 제단 폐허`는 맵에 없으므로 짓지 않음): ① 교차로에서 하늘의 부서진 `CrownOfBalance`(약 (0,350,0))를 올려다봄 ② 분수 위 `CrownShard` 빛기둥(약 (0,22,0))으로 내려옴, 조각이 빛의 성채(z≈-400)·뿔 소굴(z≈+400)로 날아가 각 진영 쪽이 빛나는 짧은 컷 ③ 교차로의 내 아바타 앞에 조각 하나가 떨어짐 + "어느 편에 설래?" ④ 진영 카드(설명 줄은 이미 채워진 상태). 안개(120~650) 때문에 가까운 컷만, 위에서 전체를 내려다보는 장면 없음(전체 맵은 지도 전용, A12). 자막은 `Config.Story`의 세 줄(GDD §1-1).
- 구현: **별도 클라이언트 모듈**(자체 `IsOpen()`)로 만든다 — 메뉴 다시 보기는 진영이 정해진 뒤라 FactionPicker 안에 넣으면 동작하지 않는다. 모든 "화면 가리기" 검사(HUD `pickersOpen`, EventHUD, Panels, VitalsUI, ClassPicker)에 이 모듈을 추가하고, FactionPicker는 연출이 끝난 뒤 연다. Scriptable 카메라 트윈 + 기존 맵·Fx/파티클만(새 그림 없음). **건너뛰기 버튼**(PC 키·폰 버튼) 항상 표시. 연출 중 공격·스킬·물약 입력 무시, 다시 보기는 안전 지역에서만. 끝·건너뛰기·리스폰 때 CameraType Custom과 Humanoid 대상을 정확히 복구(과거 카메라 복구 버그 주의). `IntroSeen`은 DataService 기본값 + 서버가 설정. DataLoaded 뒤에만 시작해 기존 플레이어에게 번쩍 보이지 않게. 연출·선택 화면이 열린 동안 거위·괴수·전쟁 결과·현상수배 같은 서버 전체 알림은 줄 세워 뒤로 미룬다. 폰 성능·자막 크기 확인.
- 검증: 신규 접속 → 연출 → 카드 / 건너뛰기 / 재접속 시 안 나옴 / 메뉴 다시 보기 / 폰. 첫 10분 시간 재기에 포함한다(연출은 25초 이하).

### A23-11. 강화 주문서 규칙 (사용자 확정 2026-10-05 15시경)
- **모든 주문서는 성공률 10% / 30% / 70% 세 종류**다. **확률이 낮을수록 더 많이 오른다**(기본 제안: 10% = 강화 +3, 30% = +2, 70% = +1; 수치는 플레이 후 조정). 10%는 가장 드물게 떨어진다.
- **파괴는 절대 없다**(사용자: "파괴 없음 하자 스트레스 받잖아"). 강화 실패 시 강화 수치는 **그대로 유지하거나 최대 한 단계만 내려간다**. 어느 쪽을 쓸지(전부 유지 / 낮은 확률 주문서만 한 단계 하락 등)는 작업 세션이 추천안과 함께 사용자에게 한 번 묻는다. 확정 전 기본값은 "유지".
- **강화 옮기기 주문서**: 한 무기의 강화 수치를 다른 무기로 옮긴다. 이것도 10% / 30% / 70% 세 종류다. 실패하면 **원래 무기에 강화가 그대로 남고** 주문서만 사라진다. 확률별로 무엇이 다른지(기본 제안: 10% = 전부 옮김, 30% = 2/3, 70% = 1/3, 내림)는 사용자 확인.
- 이 절은 이전의 "강화는 항상 성공·실패 없음" 기본값(A22·GDD §0-1·AGENTS 페르소나)을 대체한다. 장비 파괴 금지와 능력치 판매 금지는 그대로다. 성공률·결과는 서버가 굴리고, 사용 전 화면에 성공률과 실패 시 결과("무기는 안전해요")를 보여 준다.
- 미정(작업 세션이 묻기): 최대 강화, 확률별 드랍률, 첫 주문서 보장, 환생 때 강화 처리(GDD §9 무기 초기화와 일관), 강화된 무기 판매가.

### A23-12. 드랍·아이템·주문서 세부 (사용자 확정 2026-10-05 15시대, 작업 세션 버튼 질문 → 작업 세션 보고로 기록)
- **드랍 종류:** 재료, 강화 주문서, 가끔 물약, 희귀 무기. 기여자마다 따로 굴리는 개인 보상이다(뺏기 없음). 서버만 굴린다.
- **받는 법:** 몬스터가 죽는 순간 자동으로 받고 "+슬라임 젤리" 같은 알림을 띄운다. 바닥에는 반짝이는 연출만 있다. 보관은 메뉴의 간단한 "아이템" 목록이며, 가방·줍기는 없다(GDD §11 유지). → **A23-19로 대체(2026-10-05): 가방 창(BB7)을 만든다. 바닥 줍기는 여전히 없다.**
- **재료:** 베타는 대장간 "재료 팔기"까지만, 장인 제작은 정식(12/19). 아이템 거래 없음(1:1 거래 금지 유지).
- **대박 드랍:** "레벨1 몬스터(슬라임)"에서 극히 낮은 확률로 대박 아이템이 나온다. 플레이어 레벨과 상관없다. 사냥터에 레벨 상한이 없으니 고렙도 아이템 때문에 슬라임을 잡는 그림이다. 레벨 봉인 버튼은 없다. **자동 전투 킬도 대박 굴림에 포함**한다(사용자 선택, 검토 세션의 "수동만" 권고는 거절됨).
- **전설 무기 세기:** "적당히 셈" = 상점 최고 무기(티어3, 피해 38)의 약 2배. 오래 쓸 수 있지만 결국 상위 티어로 바꾼다. PvP 피해 상한(GDD §6)은 그대로 적용한다.
- **주문서(A23-11 확정값):**
  - 실패하면 **50% 확률로 한 단계 하락(최소 +0), 50% 유지**. 파괴 없음.
  - 강화 옮기기 주문서는 확률(10/30/70%)만 다르고, **성공하면 항상 전부 옮긴다**. 실패하면 원래 무기에 그대로 남는다.
    - **손해 0 규칙**(작업 세션이 정함, 검토 동의 2026-10-05): 받는 무기 = min(10, 받는 쪽 +M + 보내는 쪽 +N)이다. 10을 넘는 몫은 보내는 무기에 남으므로 강화가 사라지는 경우가 없다.
    - 받는 무기가 이미 +10이거나 보내는 무기가 +0이면 거절하고 주문서도 쓰지 않는다.
  - **최대 +10, +1마다 공격 +10%**. **무기(티어)마다 따로 저장하고, 환생해도 유지**한다.
    - (갱신) A23-14로 환생은 레벨만 초기화하므로 무기 보유와 강화가 그대로 남는다.
  - 첫 왕 슬라임 처치 때 70% 주문서 1장을 보장하고, 사용법 안내를 한 번만 띄운다.
- **기본값은 작업 세션이 정한다:** 드랍률·판매가·물약 드랍률. 15분 측정에 "드랍 수입"을 따로 기록한다.
- **같은 시각 사용자 확인(작업 세션 보고):**
  - "바라보는 방향 = 공격 방향": 사용자가 직접 요청했다. 모든 직업(궁수·마법사·성기사)이 캐릭터가 보는 방향으로 공격하고, 자동 전투는 대상 쪽으로 돈다. GDD §11 "조준 없음"을 대체한다. 폰 체감은 아직 확인하지 않았다.
  - 마법사 상향: 공격 간격 1.1초, 평타 MP2.
  - 물약 가격: 25골드.
  - 내 이름표: 나한테만 숨기기.

### A23-66. 미니맵 내 화살표가 캐릭터가 보는 쪽을 가리킨다 (사용자 2026-10-07)
- 사용자: "조그만한 지도 그것도 캐릭터의 시선 따라서 뾰족한 게 바뀌어야 돼 옆으로 시선돌리면 < 이렇게"
- A23-51의 '내 화살표는 늘 위'를 대체한다. **미니맵은 카메라가 보는 쪽이 위**로 돈다(화면 앞 = 지도 위, 부드럽게). **내 화살표는 캐릭터가 바라보는 쪽**으로 돈다: 카메라 기준으로 캐릭터가 왼쪽을 보면 '<', 오른쪽이면 '>', 카메라 쪽(뒤)을 보면 아래.
- A23-65(카메라가 뒤를 따라감)와 함께 쓰면 앞으로 걸을 때 화살표는 위, 옆으로 돌거나 싸우며 몸을 돌리면 그쪽을 가리킨다. 'N'은 테두리에서 북쪽을 따라 돈다(그대로). 전체 지도(M)는 북쪽 위 고정 + 화살표 = 캐릭터 방향(그대로).
- 담당 이미지 개발(MiniMap.luau). 화살표 회전도 부드럽게(순간 점프 없이), 작은 각도 변화는 쓰지 않음(MinTurn).

### A23-65. 카메라가 캐릭터 뒤를 따라간다 (사용자 2026-10-07)
- 사용자: "캐릭터가 움직일 때 카메라도 같이 움직이면 좋겠어. 캐릭터의 뒤를 따라서!"
- **움직일 때 카메라가 천천히 캐릭터 등 뒤로 돌아온다**(앞으로 걸으면 자연스럽게 뒤에서 보게). PC·폰·패드 모두.
- 손으로 돌리기는 그대로(A23-51: 오른쪽 드래그·손가락 드래그). 사람이 돌린 직후 약 1.5초는 자동으로 되돌리지 않는다. 가만히 서 있거나 뒤로 걸을 때는 돌리지 않는다(뒷걸음 때 카메라가 빙글 도는 멀미 방지).
- 부드럽게(초당 회전 상한, 흔들림 끄기면 더 느리게). 싸울 때 FaceTarget으로 몸이 돌아도 카메라가 휙 돌지 않게 한다(공격 중 0.5초는 따라가지 않음).
- Settings에 'Camera: Follow / Free' 한 줄(기본 Follow). 담당 개발 1(CameraFollow.luau). 처음엔 Roblox 기본 Follow 모드로 시험해 보고, 싸움 중 휙 도는 문제가 있으면 직접 만든 부드러운 따라가기로 바꾼다.

### A23-61. 기본 공격은 앞쪽 반원 — 옆에 있는 몬스터도 맞는다 (사용자 2026-10-06 밤)
- 사용자: "다른 게임들도 정면 보고 치는데 옆에 있던 애들도 죽더라고." (PC 왼쪽 클릭이 옆 몬스터를 헛치는 문제를 다시 생각하며)
- **기본 공격 판정 = 바라보는 방향 기준 앞쪽 반원(좌우 90°씩 = 코드 `AimCone = 90`, AimCone은 반각)**, 모든 직업·맨손. 뒤쪽은 그대로 안 맞는다(이전 "앞을 보고 친다" 결정 유지, 폭만 넓힘). 사거리·대상 수(Targets)·Splash는 그대로.

### A23-56. 게임성 먼저·퀘스트 많이·제작 품질은 타이밍 미니게임 (사용자 2026-10-06 저녁)

### A23-55. 왕관은 욕심 때문에 깨졌다 (사용자 결정 2026-10-06 저녁; story_depth §8 질문 1의 답, 검수 추천안 대신)
- 사용자: "'내가 갖지 못하면 누구도 갖지 못한다.' 이게 더 나을 것 같음. 황금 거위도 동화에서 욕심 때문에 거위의 배를 가르잖아. 욕심 때문에 깨진 거라고 하자. 균형의 왕관이 깨진 걸 서로의 탓을 하는 거지, '저 녀석들이 그랬네' 하면서. 사이가 그냥 데면데면했는데 나빠진 거야."
- **이야기 뿌리:** 균형의 왕관은 날마다 세상에 조금씩 빛과 균형을 나눠 주던 보물이었다(황금 알을 낳는 거위처럼). 누군가 그걸 **한꺼번에 다 가지려다** 손에 넣지 못하자 "내가 못 가지면 아무도 못 가져!" 하고 깨뜨렸다 — 동화에서 욕심 때문에 거위 배를 가른 것처럼, 남은 건 조각뿐.
- **누가 했는지는 아무도 모른다.** 빛과 뿔은 원래 데면데면한 이웃이었는데, 왕관이 깨진 뒤 서로 "저 녀석들이 그랬어!" 하며 탓하다 사이가 확 나빠졌다. 조각을 주운 사람은 그걸로 처음 한 일에 따라 후광이나 뿔이 돋았다. 장인 길드는 "누가 깼든 고치는 게 먼저"라며 어느 편도 들지 않는다.
- **풀어 가는 법:** 레벨이 깊어질수록(A23-52) 플레이어는 '누가 깼나'를 조금씩 알아 간다 — 진짜 범인은 한쪽 진영이 아니라 '혼자 다 갖고 싶은 마음' 그 자체이고, 그 마음은 빛에도 뿔에도 누구에게나 있다는 것(설교 없이, 마지막 장의 질문으로). 황금 거위가 조각을 품고 있는 것도 이 동화와 이어진다(거위 배를 가르려는 사람 = 욕심, 거위를 구하는 사람 = 나눔).
- **결말 반전(사용자 같은 날 보강):** "그래서 결국 왕관은 누가 깼나? 사실은 이것 때문에 서로 항상 긴장하고 살았던 거지. 균형의 왕관이 있어야만 균형을 이룰 거라고 모두가 믿었던 거야. 그런데 왕관을 깬 게 그냥 아이면 어때? 그 본질을 보는 것 — 오히려 균형의 왕관 때문에 우리가 더 화합을 못 한다고 보는."
  - **(사용자 같은 날 다시 보강: "뿔과 빛의 아이들의 결합으로 깼다고 하자")** → 왕관을 깬 건 **빛의 아이와 뿔의 아이, 둘이 함께**다. 어른들이 서로 미워하는 사이에 몰래 친구가 된 두 아이가 손을 잡고 깼다 — 화합 자체가 왕관을 깬 셈. 아래 '한 아이'는 이 '두 아이'로 읽는다.
  - **진실(마지막 장에서만 밝힘):** 왕관을 깬 건 빛도 뿔도 아닌 **한 아이**다. 모두가 '왕관이 있어야만 균형이 지켜진다'고 믿어서 왕관을 지키고 노리느라 늘 긴장하며 살았다. 아이는 그 본질을 보았다 — 왕관 때문에 오히려 서로 화합하지 못한다는 것. 그래서 일부러 깼다(욕심이 아니라 그 반대).
  - "내가 못 가지면 아무도 못 가져!"는 **어른들이 지어낸 소문**이고, 양쪽이 서로 탓하는 근거가 됐다. 욕심은 왕관을 깬 아이가 아니라 **왕관을 서로 가지려던 모두**에게 있었다.
  - 결말의 질문: 균형은 왕관이 아니라 우리가 날마다 고르는 것(GDD §0 — 모든 행동이 천사 아니면 악마 쪽으로 기운다). 아이는 벌받지 않고, 설교 없이 질문으로 끝난다. 어린이용 안전(아이를 탓하거나 무섭게 그리지 않음).
- 쓰는 곳: 오프닝 다시 만들기(A23-44) 대사·장면, `Config.Story` 세 줄(GDD §1-1), 3~5장 복선(`docs/design/story_depth_2026-10-06.md` §8에 이 답을 적음). 화면은 쉬운 영어(A23-48). 예: "Someone wanted the Crown all to themselves." / "'If I can't have it, no one can!' CRACK." / "Now each side says the other did it."

### A23-54. 계급마다 멋있어지는 뿔·후광 (사용자 2026-10-06 저녁, 참고: 테일즈런너 악마 뿔 의상 사진)
- 사용자: "악마 뿔 이것 좀 봐봐, 이런 식으로" — 계급이 오를수록 뿔이 작은 뿔 → 크게 휜 뿔 → 장식·불꽃 끝으로 점점 멋있어지는 모습.
- **뿔 계급 R1~R5(뿔 군단)와 후광 계급 R1~R5(빛의 기사단)를 같은 무게로** 디자인한다(공정). 계급이 오르면 모양이 바뀌고(IDEA-MARKGROW는 같은 계급 안에서 조금씩 커지기), 맨 위 계급은 은은한 빛·불씨(뿔)·빛 고리 두 겹(후광) 같은 특별한 끝. 장인 길드는 톱니·청록 크리스털 표시를 같은 방식으로 계급 3단계.
- **참고는 모양·성장 느낌만.** 그 게임의 그림·의상을 베끼지 않는다. 참고 사진의 노출 옷차림은 절대 따르지 않는다(Hard rule 1) — 우리 캐릭터는 플레이어 본인 아바타에 뿔·후광 액세서리만 붙는다. 무섭지 않고 귀엽게 멋있게(둥근 끝, 장난감 광택).
- **사용자 선택(2026-10-06 저녁, c98dfec 시트):** 뿔 = A줄(작은 혹 → 휜 뿔 → 줄무늬 큰 뿔 → 금 고리+빛 → 말린 뿔+불씨), 후광 = B줄(은 고리 → 별 → 날개+다이아 → 해 문양+날개 → 두 겹+해+왕관 끝+큰 날개, 계급 배지와 한 세트), 장인 = A줄(청록 톱니 → 톱니+크리스털 → 톱니 관). 이 2D로 3D 진행.
- 순서(A23-47): 2D 시안 시트(R1~R5 × 뿔·후광, 앞·3/4, 멀리서도 계급이 읽히게) = 이미지 생성 2 → 사용자 → 3D(무료 생성 먼저, 안 되면 Tripo — 크레딧 먼저) = 이미지 생성 1 → 붙이기(CharacterVisuals, 계급별 메시·크기) = 게임성 개발 2 → 메인 확인 = 게임성 개발 1. 계급 배지 그림(9be09d8)과 색·모양을 맞춘다.

### A23-52. 이야기는 레벨이 오를수록 깊어진다 (사용자 2026-10-06 저녁)
- 사용자: "스토리가 지금은 간단하지만 점점 레벨이 오르고 깊숙하게 들어갈수록 조금 더 심오하게 가자. 악은 무엇을 위하여 악을 행하고, 선은 무엇을 위하여 선을 행하나. 선은 언제나 흥미로우며 악은 언제나 지루하다, 뭐 이런 식으로 ㅋㅋ 서브 퀘스트들도!"
- **방향:** 처음(Lv1~10)은 지금처럼 쉽고 밝게. 레벨·지역이 깊어질수록 메인·서브 퀘스트가 '왜'를 묻는다 — 빛은 무엇을 위해 지키는가, 뿔은 무엇을 위해 빼앗는가, 장인은 왜 어느 편도 들지 않는가. 양쪽 모두 이유가 있고, 고르는 사람이 답을 만든다(GDD §0: 모든 선택이 천사 아니면 악마 쪽).
- **주제 한 줄:** "선은 늘 새롭고 흥미롭고, 악은 결국 늘 같은 일을 되풀이해 지루해진다." 악을 고른 플레이어를 꾸짖지 않고, 이야기 안에서 스스로 느끼게 한다(뿔 쪽 이야기도 재미있게, 다만 '되풀이'가 보이게).
- **어린이용:** 8~12살이 읽는 쉬운 영어 짧은 문장(A23-48), 무섭거나 잔인한 장면 없음, 설교 없음, 질문으로 끝내기.
- **어른도 재미있게(사용자 같은 날: "어른이 하기에도 나쁘지 않았으면 좋겠어. 이스터에그처럼 현실 풍자 같은 것도"):** 아이에게는 그냥 웃긴 장면, 어른에게는 한 겹 더 보이는 농담(두 겹 대사). 숨은 이스터에그(찾으면 짧은 대사·작은 칭호, 능력치 없음). 풍자는 **일상·회사·인터넷·게임 문화**(끝없는 회의, 줄 서기, '좋아요' 집착, 약관 동의, 매일 출석 보상, 확률 뽑기, 패치 노트, 로딩 화면 팁 같은 것)만. **실제 정치인·정당·종교·국가·실존 인물·실제 브랜드는 쓰지 않는다**(Roblox 규칙, 어린이 안전). 비꼬는 대상은 '행동'이지 '사람 무리'가 아니다.
- 설계: 검수가 레벨대별 장(章)·서브 퀘스트 주제를 정리하고(`docs/design/story_depth_2026-10-06.md`), 데이터는 게임성 개발 2(Config.StoryQuests, 영어), NPC·연출은 게임성 개발 1. 베타에 들어갈 몫과 정식 몫을 문서에서 나눈다.

### A23-51. 실시간 지도는 내가 가는 방향으로 돈다 + 내 화살표 디자인 + 오른쪽 마우스 회전 (사용자 2026-10-06 17시대)

- **왼쪽 드래그 카메라 회전은 없앤다**(사용자 같은 날: "왼쪽 드래그는 없애줘. 보통 왼쪽 드래그로 안 하더라고?"). A22·AGENTS의 'left-drag rotates the camera'를 대체한다. 왼쪽 클릭은 공격 1번 그대로(누르고 끌어도 반복·회전 없음). 폰은 Roblox 기본(화면을 손가락으로 끌어 회전) 그대로.

- **내 화살표 그림:** 밋밋한 세모 대신 게임 스타일 화살표(흰색으로 그려 코드로 색, 굵은 진한 외곽선, 진영 색 칠, 작은 크기에서도 앞이 분명). 다른 플레이어 점과 확실히 다르게. 그림 = 이미지 생성 2, 지도 회전·연결 = 이미지 개발.

### A23-47. 모든 게임 디자인 = 2D 시안 → 물건 하나씩 2D → Tripo, 그리고 넓고 꽉 찬 세계 (사용자 결정 2026-10-06 밤; A23-41의 세계 에셋 '무료 먼저'와 A23-46의 '200×200까지만·무료 생성 먼저'를 대체)
- 사용자: "게임 디자인 모두 2D 디자인 시안 먼저 > 시안에 나오는 모든 것 각각 2D로 만들기 > TRIPO로" / "다른 RPG 게임들 로블록스 거 대강 해 보니까 되게 넓은데, 꽉꽉 채워져 있더라고."
- **만드는 순서(마을·스폰·가게·사냥터·소품·몬스터·NPC 등 모든 게임 디자인):**
  1. **2D 시안**(Firefly, 장면 전체 한 장): 검수가 100% 확대로 먼저 보고 사용자에게 보여 준다(가까운 안 고르기는 세션에 맡김, A23-25).
  2. **시안 속 물건을 하나씩 2D로**: 한 장에 물건 하나, 3/4 앞모습, 물건 전체가 그림 안, 단색 배경, 글자 없음, 시안과 같은 색·모양. 누끼를 딴다. 물건 목록은 `docs/design/kit_<구역>.md`(이름·크기(스터드)·몇 개 놓을지·누가 그렸는지).
  3. **Tripo로 3D**(image-to-model, 중요한 건물은 multiview) → Blender 정면 렌더로 시안과 비교 → WorldKit에서 크기·색 맞추기 → 메인 Studio.
- **무료 에셋은** 모양이 개성을 정하지 않는 바닥 덮개(풀 포기·작은 자갈 등)에만, 시안 색과 맞을 때 쓴다. 시안에 나오는 물건은 Tripo로 만든다(모양이 시안과 같게). 유료 모델은 Tripo로도 안 될 때만. 동작(애니메이션) 팩은 A23-41 그대로.
- **크레딧:** 소품 약 40, 건물 약 60(지난 작업 기준). 묶음마다 합계를 사용자에게 먼저 알린다. 2026-10-06 남은 크레딧 3,715.

### A23-43. 게임 기본 언어 = 영어 + 한국어 (사용자 결정 2026-10-06 오후; A23-25의 '영어는 정식'과 A23-35의 한글 글꼴 고민을 대체)

- **퀘스트 목표 마커:** 지금 할 퀘스트의 목표(Guide: 사냥터·대장간·분수·연못·우리 마을·거위 등)에 화면 위로 뜬 작은 아이콘 + 거리 글자("33m")를 보인다. 항상 앞에 보이고(가려지지 않음), 크기는 거리와 상관없이 일정, 목표에 가까워지면(약 10m) 사라지거나 옅어진다. 화면 밖이면 화면 가장자리에 같은 아이콘 + 방향 화살표. 한 번에 하나(지금 고정된 퀘스트 줄의 목표). 거리 = 스터드 ÷ 3.5를 반올림해 m로.
- **큰 3D 장소 글씨(간판·빌보드)는 없앤다.** 지금 어디인지는 HUD v2 가운데 위 지역 칩(A23-26)이 알려 준다. 마을 상점 이름처럼 가까이서만 보이는 작은 이름표는 남겨도 된다.
- 담당: 마커·가장자리 화살표·미니맵 목표 점은 이미지 개발(HUD v2와 같은 '목표 위치' 데이터), 아이콘(흰색 마름모, 코드로 색, 화살표 글리프)은 이미지 생성 2, 큰 3D 글씨 제거(MapBuilder 등)는 게임성 개발 1. 지금 있는 초원 빔·이동 창은 마커가 들어간 뒤 겹치지 않게 정리한다.

### A23-35. 글씨: 꾸민 글자 + 중요한 제목만 그림 글자 (사용자 결정 2026-10-06)
> **같은 날 사용자 정정 — ②(그림 글자)는 취소:** "이미지로 글씨를 만들어서 박는 건 안 될 것 같다. 영어나 다른 언어로 자동 번역이 안 되잖아." → **모든 글자는 TextLabel(꾸민 글자 ①)로만** 쓴다. 제목도 ① 스타일(더 큰 굵기·두꺼운 테두리·그라데이션) + 그림 판(TitleRibbon·PanelHeader) 조합으로 게임 글씨 느낌을 낸다. 아래 ②와 글꼴 다운로드·tools/make_title.py는 하지 않는다. Roblox 자동 번역이 TextLabel에 걸리도록 글자는 Config 표에서 읽는다.
- 확인된 사실(이미지 개발 글꼴 견본, art/review/font_samples_2026-10-06.png): Roblox에서 한글은 어떤 글꼴을 골라도 같은 대체 한글 글꼴로 나오고 굵기만 바뀐다. 글꼴 가족은 영어·숫자만 바꾼다(귀여운 영문 글꼴을 쓰면 한 줄에 두 글꼴이 섞여 보인다).
- 사용자: 두 방법을 합친다 — **① 보통 글자는 꾸민 글자**(TextLabel + 굵기 + 테두리·그라데이션) **② 중요한 제목만 그림 글자**.
- ① 꾸밈 규칙(UIKit 글자 스타일, 이미지 개발 소유): 어두운 바탕·3D 위 = 흰→크림 그라데이션 + 진한 남색 테두리 2px(크기에 맞춰 1~3px), 밝은 판 위 = 진한 남색 글자(테두리 없음), 흰 글자+그림자는 밝은 바탕에 쓰지 않는다. 굵기는 제목·버튼 Heavy/Bold, 본문 Regular/Medium. 영어·숫자 글꼴은 대체 한글과 어울리는 무난한 산세리프 하나로 통일(귀여운 영문 장식 글꼴 섞지 않기). 스타일 이름 5개 이하(제목·버튼·본문·숫자·이름표).
- ② 그림 글자: **Firefly로 한글을 그리지 않는다.** 무료 OFL 한글 글꼴(Google Fonts의 Jua·Do Hyeon·Black Han Sans·Gaegu·Dongle 중 사용자가 고른 하나, 사용자 다운로드 허락 2026-10-06)로 로컬에서 글자를 만들고(PIL), 테두리·광택·그림자를 입혀 투명 PNG로 만든다. 대상은 고정된 큰 제목만(게임 로고 글자, '어느 편에 설래요?', 진영 이름 3, 창 제목, '레벨 업!'·'승리!'·'호박 대왕 등장!' 같은 큰 알림 등 약 20~30개). 같은 그림을 영어판으로도 만든다(정식 때 영어 켜기). 바뀌는 글(숫자·이름·설명)은 계속 ①.
- 담당: 그림 글자 도구·견본·제작 = 이미지 생성 2, 업로드·UIKit 글자 스타일·키 연결 = 이미지 개발. 글꼴 파일은 `art/fonts/`(OFL 라이선스 파일 같이), 글자 목록은 Config 표(KO/EN).

### A23-34. 맨손으로 시작·전투력 0 (사용자 결정 2026-10-06)
- 사용자: "처음에는 전투력이 0이어야 함, 무기 얻는 퀘스트가 있으니까 처음에는 손에 무기가 없어야 돼!"
- **새 플레이어는 무기 없이(맨손) 시작한다.** 저장 기본값은 무기 없음(예: WeaponTier = 0, WeaponOwnedMask = 0). A23-4의 '시작 무기 비트는 항상 켜짐'과 Config.Weapons Tier 1 '무료 시작 무기'를 대체한다. 이미 무기를 가진 옛 세이브는 그대로 둔다.
- **처음 전투력은 0**이다: Lv1·무기 없음·펫 없음이면 0이 되게 Config.CombatPower 계산을 맞춘다(레벨 항은 Lv1에서 0).
- **맨손 공격:** 모든 직업이 무기 없이 주먹으로 가까이 때린다(작은 피해, 슬라임은 몇 대에 잡힘 — 첫 임무 5마리가 2~3분 안에 끝나게). 자동 전투·스킬 Q는 맨손이어도 쓸 수 있다(직업 스킬이라서). 손에는 아무것도 들지 않는다(헤일로·뿔은 그대로).
- **첫 무기는 퀘스트로 받는다(검수 결정, 사용자가 바꿀 수 있음):** 첫 임무(슬라임 5마리, 150골드) 다음 메인 M1_1 '대장장이에게 가기'에서 대장장이가 **직업 기본 무기(Tier 1)를 무료로** 준다. 받을 때 "첫 무기를 받았어요! 전투력 0 → N" 알림. 150골드로 나무 무기(Tier 2)는 원하면 바로 산다(강요 없음).
- 진영 카드·직업 고르기·안내 문구 중 '시작 무기'를 말하는 곳은 바꾼다. 환생(A23-14)은 무기를 그대로 두므로 맨손으로 돌아가지 않는다.

### A23-33. 화면을 이루는 모든 것을 디자인 (사용자 결정 2026-10-06)
- 사용자: "화면을 이루는 모든 것을 디자인해야 돼. 지금은 나무도 그냥 그 위에 무늬만 얹은 것 같거든? 3D도 로블록스 것 괜찮은 것 있으면 사용하고, 진짜 정 아니면 Tripo로 만들어도 돼."

- 맡는 곳: 이미지 생성 1이 세계 디자인을 이끈다(사냥터별 소품 목록 + Firefly 콘셉트 시트 → 3D 구하기 → 소품 키트). 소품 키트는 세 번째 연습 장소 `build/WorldKit.rbxlx`(메인 장소 복사본)에서 만들고, 모델은 `art/models/worldkit/*.rbxm`으로 내보낸다. 메인 장소 배치(MapBuilder·preview_map의 공 나무 등을 키트 모델로 바꾸기)는 게임성 개발 1이 한다. 베타 우선순위: 교차로 → 빛·뿔 마을 → 말랑 초원 → 호박밭 → 고블린 숲 → 해골 폐허.

### A23-30. 사냥터마다 한 가족·한 분위기 (사용자 결정 2026-10-06, 검수 세션 어울림 시안 질문)
- 사용자(A~E 비교 사진을 보고): "던전에 맞게 해줘. 슬라임은 슬라임만 나오게 고블린은 고블린! 호박은 호박! 이런 식으로 그거에 맞게 또 조명 새 땅 이런 것도 맞춰서 해야지".
- **몬스터:** 사냥터 하나에는 한 가족만 나온다. 말랑 초원 = 슬라임·왕 슬라임, 고블린 숲 = 고블린·고블린 우두머리, 해골 폐허 = 해골 병사·해골 기사. **핼러윈 몬스터(호박 슬라임·꼬마 유령·박쥐 고블린·호박 대왕)는 따로 '호박밭' 사냥터**에 모은다(시즌이 꺼지면 호박밭도 닫히거나 비고, 초원·숲 마릿수는 시즌과 상관없이 원래대로 — 'Takes' 빼기). 퀘스트 집계(QuestAs)·대왕 안전 규칙(A23-27)·11/9 종료(A23-28)는 그대로다. 호박밭 위치는 게임성 개발이 지도에서 정한다(초원 동쪽 대왕 자리 근처 추천, 새싹도 갈 수 있게).
- **분위기:** 바닥 그림과 조명을 사냥터마다 맞춘다. 기준은 비교 사진의 E(밝은 장난감 조명 + 새 땅 그림)이고, 사냥터마다 색만 다르게 한다: 초원 = 밝은 한낮·초원 풀, 고블린 숲 = 초록 그늘빛·숲 바닥, 해골 폐허 = 푸른 달빛 느낌·돌바닥, 호박밭 = 주황·보라 노을·호박밭 흙, 빛의 마을·뿔 마을 = 진영 색. 어디서든 몬스터가 '그 자리 빛'을 받아 스티커처럼 보이지 않고, 어두운 곳도 몬스터가 잘 보여야 한다.
- 이 결정은 A9-3의 '지역별 ColorCorrection 금지'를 **대체**한다: 지역 분위기는 클라이언트가 들어간 사냥터에 맞춰 부드럽게(1~2초) 바꾸고, 전쟁 하늘(WarService의 Neutral/Dawn/Eclipse)과 겹쳐도 몬스터가 보이게 한다. Atmosphere 금지는 그대로다(FogColor 전쟁 하늘을 가리므로).

### A23-22. 주간 랭킹 보상과 무단 PvP 벌칙 (사용자 결정 2026-10-05 저녁, 검토 세션 질문 2번)
> 판 목록과 장인 길드 '사냥' 판 보상은 A23-23이 대체한다.
- 사용자: "명예 악명 1, 2, 3위 모두 동일하게 좋은 거 해주고, 내가 말한 거는 pvp를 너무 무단으로 한다던가 하는 애들을 자동 전투 못하고 경험치 줄어들고, 전투력은 그대로, 드랍율 조정하는 걸로".
- **주간 랭킹 보상(빛·뿔 똑같이):** 주간 명예 랭킹 1~3위와 주간 악명 랭킹 1~3위는 **같은 보상**을 받는다. 다음 한 주 동안 보상이 유지된다. 세부는 검토 세션이 정했다.
  - 능력치 없는 순위 칭호(예: "이번 주 명예 1위" / "이번 주 악명 1위").
  - 경험치 +10%, 드랍률 +10%(대박 확률은 제외).
  - 전투력·능력치 보너스는 없다(PvP 공정).
  - 랭킹 점수는 공정 점수(BB10)로 센다: 비슷하거나 센 상대만, 친구 제외, 같은 상대 주 3번까지. 장인 길드는 주간 '사냥' 판에 같은 보상을 받는다.
- **무단 PvP 벌칙:** 기존 깡패 규칙(`Config.Bully`: 약한 상대·막 부활한 상대·같은 상대 반복 KO)에 걸려 깡패 단계가 1 이상인 동안 적용한다.
  - 자동 전투를 쓸 수 없다. 켜져 있으면 꺼지고, 이유를 안내한다.
  - 경험치 ×0.5, 드랍률 ×0.5(**대박 확률도 절반**. 첫 왕 슬라임 70% 주문서 1장 보장은 한 번뿐인 지급이라 그대로).
  - **전투력은 그대로**다. 새 벌칙으로 전투력 숫자나 능력치를 깎지 않는다. 기존 깡패 단계의 크기·피해 감소(PerStack)는 그대로 둔다.
  - 단계가 다 사라지면(5분마다 1단계 감소) 벌칙도 끝난다.
  - 화면에 "깡패 벌칙: 자동 전투 불가 · 경험치·드랍 절반 (N분)"을 보여 준다.
- 뿔 군단의 악명·계급 자체에는 벌칙이 없다. 정당한 약탈·현상금 사냥은 손해가 없다.

- **원한 유령 붙잡기 (PvP 공정성):**
  - 털린 피해자는 부활한 뒤 도둑의 원한 자루가 열려 있는 동안 [유령으로 붙잡기]를 누를 수 있다.

  - '놓아주기'(몫을 도둑에게 넘기기)는 넣지 않는다. 부계정 골드 통로가 되기 때문이다. 명예 보상도 없다.
  - 원한 골드 우편(같은 문서 P3)과 같이 들어간다.

## A22. 사용자 의사 변경: 수동 전투·MP 스킬·첫 임무 수락 (2026-10-04; A23이 자동 전투·보상 부분을 대체)

**사용자가 기존 자동 전투 방향에서 마음을 바꿔 수동 전투를 선택했다.** 이 절은 아래 A1–A21과 TECH_SPEC의 자동 공격·충전·PERFECT·자동 발사·스택 조건·다음 해금 예고 및 옛 개인 슬라임 튜토리얼 설명보다 우선한다. 나머지 서버 권한·보상·안전 검증은 유지한다.

- **입력:** 공격 버튼·키 또는 짧은 클릭 1회에 수동 공격1회만 요청한다. 누르고 있기·이동·카메라 회전으로 반복 공격하지 않는다. 왼쪽 버튼 드래그는 회전, 짧은 클릭은 공격이다. 서버는 준비·직업 선택·생존·진영·거리·재사용 제한 등을 검증하며 직업 미선택 `Swing`을 거절한다.
- **스킬:** 전투 충전 게이지, PERFECT, 자동 발사와 최소10스택 같은 선행 조건을 폐기한다. 기존 `Release`는 수동 기본 스킬 경로로 쓰며 MP와 재사용 시간으로 제한한다. 현재 `Config.BasicSkill`의 비용은20MP·재사용3초이고 플레이 후 조정할 수 있다. MP 부족·거절 시 자원/재사용 처리, 사망·리스폰·직업 변경은 재검증한다. 전쟁 점수 표시와 HP/MP/XP 바는 전투 충전 게이지와 구분한다.
- **호환 흔적:** 현재 소스에 남은 `Config.Charge`, `SetAutoAttack`, `GetCharge` 등 이름은 과거 코드/검사 호환용이다. 활성 자동 공격·충전 시스템을 의미하지 않으며 이를 근거로 기능을 복구하지 않는다. `SkillReadyAt`으로 현재 기본 스킬 재사용 시간을 표시한다.
- **클라이언트·퀘스트:** HUD/Fx의 충전 링·숫자·PERFECT·자동 공격 버튼/키·자동 발사 효과와 “다음 해금” 예고를 제거한다. `Release` 퀘스트는 서버가 인정한 수동 스킬 사용 횟수로 진행하며 과거 `MinStacks`를 요구하지 않는다. 빛의 동료 치유는 유지하되 충전 공유는 없다. 카드 그림 속 옛 문구는 디자인 후순위로 남을 수 있고, 이를 고쳤다고 보고하거나 승인 아트를 임의 교체하지 않는다.
- **미완료 확장:** 요구 레벨을 만족해 스킬을 배우고 빈 칸에 장착하는 방향은 확정됐지만 학습 데이터·NPC·슬롯은 미완료다. 전직도 후속이며 현재 기본 스킬이 있다는 이유로 습득/장착/전직 완료라 하지 않는다.
- **첫 임무:** `Config.Tutorial.Welcome`의 진영별3쪽 대화를 기존 승인 초상화와 Panels로 표시한다. `RequestTutorial`/`AcceptTutorial`은 인자0개이며 서버가 준비·생존·선택·진행·호출 간격을 확인한다. 닫기는 수락이 아니고 메뉴에서 재개할 수 있다. 수락 전 초원 이동/처치는 수락을 대신하지 않는다. 수락 → 초원 → 슬라임5마리 → 기존120골드 보상이며 마을 개인 슬라임은 생성하지 않는다. 기존 `TutorialStep`·`TutorialKills`·수령 완료 상태를 보존하고 중복 보상을 막는다. 월드3D 안내자는 아직 없다.
- **검증 경계:** 관련 변경은 미커밋 소스에 반영돼 있으나 최신 실제 PlayerScripts·서버 통합, 직접 마우스/터치 체감, 실제 DataStore 재접속·다인·자연스러운 첫10분은 합격 전이다. 기존 오프라인 증거와 실플레이를 구분한다. 이번 갱신은 문서만 수정하며 실제 개발·Studio 검증은 사용자 지정 **2026-10-06(화)**에 재개한다.

## A1. Custom 3D model override (monsters, bosses, golden goose)

The game must run with the procedural Part-built rigs, but the creator will later drop in custom 3D models
(made from images via Tripo 3D, imported with Studio's 3D Importer). Support this WITHOUT code changes:

- Folder `ServerStorage.CustomModels` (created by MapBuilder or MonsterService at start if missing; may be empty).
- For a monster with Config id `<Id>` (e.g. `Slime`, `BigSlime`, `Goblin`, `GoblinBrute`, `Skeleton`, `SkeletonKnight`)
  and for the golden goose (`GoldenGoose`): if `ServerStorage.CustomModels:FindFirstChild(<Id>)` is a `Model` (or a
  `MeshPart`/`BasePart`), the owning service uses a CLONE of it as the VISUAL body instead of the procedural body:
  - Keep the existing gameplay rig (invisible HumanoidRootPart + Humanoid + hitbox) exactly as specified; the custom
    visual is purely cosmetic.
  - Every BasePart of the clone: `Anchored = false`, `CanCollide = false`, `CanQuery = false`, `CanTouch = false`,
    `Massless = true`; weld every part to the root with `WeldConstraint`s.
  - Scale the clone (`Model:ScaleTo`, or `Size` for a single part) so its bounding-box height matches the procedural
    body's height for that monster (`Config.Monsters[Id].Scale` etc.), then position it so its bottom sits on the floor
    under the HumanoidRootPart and it faces the root's LookVector.
  - Golden (4% variant) monsters: tint the custom visual by adding a gold `Highlight` (FillColor gold, FillTransparency ~0.5)
    instead of recoloring parts.
  - Simple "alive" motion for custom visuals: a small vertical bob/squash tween is enough (no animations required).
    - (2026-10-06, 71c10bd) No server-side bob: the server must not tween Humanoid.HipHeight (it lifted whole monsters 0.18–0.45 stud off the ground). Idle/walk motion lives on the client only (MonsterMotion, Fx WOBBLE, blob shadows).
- Owners: MonsterService (monsters), the service that spawns the golden goose (goose). Print once per Id at startup:
  `[MonsterService] custom model for <Id>: yes/no`.

## A3. Mandatory fixes from pre-implementation review (override TECH_SPEC where they conflict)

- **DataService session lock (H1):** never write `copy.SessionLock = release and nil or {...}` (Lua and/or pitfall: always
  yields the table). Use:
  `if release then copy.SessionLock = nil else copy.SessionLock = { JobId = game.JobId, Time = os.time() } end`.
- **Monster Humanoids (H2):** on every monster rig: `hum.RequiresNeck = false`; disable states
  `Dead, FallingDown, Ragdoll, Seated, Climbing, Swimming, PlatformStanding` via `hum:SetStateEnabled(state, false)`
  (death is handled by the service's own HP, not Humanoid state); `hum.HealthDisplayType = Enum.HumanoidHealthDisplayType.AlwaysOff`;
  `hum.DisplayDistanceType = Enum.HumanoidDisplayDistanceType.None`. Knockback must not topple them.
- **Manual beats auto (H3):** manual and auto swings share the swing cooldown, but record `lastManualAt[player]`; the auto
  loop skips a player while `os.clock() - lastManualAt[player] < cls(player).SwingInterval + Config.Combat.ManualYieldPad`
  (0.3; R1 CR-M17 — the old fixed 1.0 s was not longer than the Warrior/Mage interval). A manual swing request is accepted
  whenever the cooldown is ready (never silently dropped because auto consumed it).
- **Top bar inset (H4, revised by R1 CR-L34):** every own ScreenGui sets `IgnoreGuiInset = true` and then
  `ScreenInsets = Enum.ScreenInsets.DeviceSafeInsets` + `SafeAreaCompatibility = Enum.SafeAreaCompatibility.None` (each in
  pcall), so content stays out of notches / the home indicator but still extends under the Roblox top bar. Therefore every
  top-anchored HUD block must still start at `Y >= GuiService:GetGuiInset().Y + 8` (fallback 64 px), and code that maps
  screen pixels into the gui must use the gui's own AbsolutePosition (it is no longer always 0,0). Never place UI in the
  top-left 0..64 px band.
- **Mobile jump button (H5):** on touch devices, read `PlayerGui.TouchGui.TouchControlFrame.JumpButton`
  (WaitForChild with 5 s timeout) AbsolutePosition/AbsoluteSize and place the main attack button up-left of it
  (fallback offset (-200, -170) from bottom-right); place release/auto buttons relative to the attack button. Re-layout on
  `workspace.CurrentCamera:GetPropertyChangedSignal("ViewportSize")`.
- **Readable text (M1):** UIScale = clamp(viewportY / 720, 0.75, 1.25); every TextLabel/TextButton gets a
  `UITextSizeConstraint` with `MinTextSize = 11` (or uses TextScaled with MinTextSize 11).
- **Monster density (M2):** add `Config.MonsterDensity = { ExtraPerPlayer = 2, MaxZoneMult = 2 }` (G1 owns Config: add it).

### A16-1 Anti-cheat movement check — LOG-ONLY for now [CR-H2]
- `Config.AntiCheat = { Enforce = false, MoveMult = 1.6, Slack = 8, RisePerSec = 60, RiseSlack = 12, TeleportGrace = 1,
  SpawnGrace = 2, PadSlack = 4, LogCooldown = 10 }`; `Config.Travel.ZoneTick` 0.5 → 0.2. A missing / non-number key uses
  the default.
- ZoneService samples each root every zone tick (`validateMove`, right after the A10 RESCUE_Y rescue). Plausible = flat move
  since the last good sample ≤ `Humanoid.WalkSpeed × MoveMult × dt + Slack` and rise ≤ `RisePerSec × dt + RiseSlack`
  (falls are never limited). An implausible move is logged at most once per `LogCooldown` s per player. Only when
  `Enforce == true` is the player pulled back to the last good position; in log-only mode the new position simply becomes
  the last good one.
- `ZoneService.IsPlausible(player, pos) -> boolean`: same test against the last sample; true when there is no sample yet,
  the character is new, the player is in teleport/spawn grace or the input is invalid. Logs failures; returns **false only
  while `Enforce == true`**, so callers can never punish anyone in log-only mode. Callers (all pcall'd, only if present):
  CombatService Swing / Release, FactionService.nearAltar.
- `ZoneService.MarkTeleported(player, seconds?)`: call right BEFORE a server-side teleport; every move is accepted for
  `seconds` (default `TeleportGrace`, NaN/negative → default, max 30) and the track restarts. Callers: ZoneService.teleport()
  (enemy-town / level bounces, A10 rescue, pads, travel), ZoneService CharacterSpawned (`SpawnGrace`), PlayerService
  (before LoadCharacter and the spawn PivotTo) and JusticeService (spawn lift), both with `SpawnGrace`.
- **Always enforced** (independent of `Enforce`): a travel-pad touch counts only when the toucher's root is within
  `max(pad.Size.X, pad.Size.Z) / 2 + PadSlack` (flat) of the pad, checked before the pad debounce; Swing / Release return
  early when `Config.ZoneAt(root.Position).MinLevel > Level` (Swing keeps its cooldown unspent, Release keeps the charge);
  target selection skips zone monsters whose zone MinLevel > the attacker's Level (personal monsters exempt).
- ProgressionService.BankAll does not consult IsPlausible (its IsTown comes from ZoneService's checked zone).
- Switch `Enforce = true` only after a playtest shows no false positives (menu travel, respawn, fall rescue, bully / kaiju
  scale changes, enemy-town bounce). It is read on every call, so it can be flipped at runtime.

### A16-2 Saved pair cooldowns [CR-M3, CR-M4, CR-L6]

- `PlayerService.PairReady(holder, otherUserId, kind, cooldown, commit?) -> boolean`: true when
  `os.time() - PairCD[key] >= cooldown`; when true and `commit ~= false` it records now (`commit = false` = look only).

- Keys in use:

  | Holder | Key | Cooldown | Meaning |
  |---|---|---|---|
  | killer | `ko:<victimUserId>` | PvP.PairRewardCooldown 300 | minted KO rewards; also the logout bounty (A16-4) |

### A16-3 Data, rejoin and shutdown [CR-M1, CR-M2, CR-M12, CR-L1, CR-L2, CR-L3]
- DataService: the per-UserId write slot is a FIFO queue (token interface unchanged); a waiter that exceeds SLOT_TIMEOUT
  removes itself and gets nil. `Load` first waits until an earlier session of the same UserId has finished `Release`
  (nil if the player leaves or SLOT_TIMEOUT passes), runs its body in pcall and always frees the slot; `Save` does too.
  Public API unchanged.

- `PlayerService.IsShuttingDown() -> boolean`: true from the start of BindToClose. Shutdown order: for every ready,

  ProgressionService does not apply CombatLogPenalty during shutdown.

  so BindToClose waits for that save as well.
- Kept across a rejoin [CR-M12]: `Config.Data.Defaults.SavedBully, SavedBullyAt, SavedStars, SavedStarsAt` (persisted, not
  mirrored). Written in PlayerLeaving, read and zeroed (one-shot) in PlayerReady, restored only for Halo/Horns:

## A20. 승인된 3단계 표정과 검증된 얼굴 메시 (2026-10-03; 실제 등록 0종)

- 남녀 직업18종은 사용자 승인한 **Neutral / Serious / SoftSmile** 세 표정부터 준비한다. 현재
  `ExpressionAssets.Costumes`와 `Monsters`는 비어 있으며 실제 업로드 ID/등록은 **0종**이다. 서비스 시작이나
  `Expression` 속성 변경만으로 표정 그림이 실제 표시됐다고 하지 않는다.
- `ExpressionService`는 서버가 조건을 정한다. 기본 Neutral, 승인된 공격 후1.2초 또는 실제 HP 감소 후0.8초는
  Serious, 유저 채팅/확인된 NPC 대화 후3초는 SoftSmile이며 전투·피격이 대화보다 우선이다. 전투가 끝나면
  남은 대화 시간 또는 기본 표정으로 돌아온다. 몬스터는 서버 WindupAt/AttackSeq/HurtSeq를 따른다.
- NPC 대화는 `Conversation=true` ProximityPrompt와 NPC 태그, 살아 있는 ready 플레이어, 활성 prompt,
  서버 거리≤MaxActivationDistance+3 및0.5초 throttle을 확인한다. 일반 상점/제단 prompt만으로 미소를 강제하지
  않는다. 채팅 내용은 이 서비스에서 저장하거나 재전송하지 않는다.
- 등록 정의에는 UV에 맞는 `Neutral`, `Serious`, `SoftSmile`의 유효한 `rbxassetid://` ID와 **MeshName**이 필요하다.
  MeshName은1~64자의 영문/숫자/밑줄/하이픈이며 `Head`는 금지한다. 대상 모델에서 유일한 MeshPart여야 하고
  **`HHC_ExpressionMeshValidated=true`** 표시를 가진 검증된 별도 얼굴 메시만 사용한다. 플레이어 얼굴은 Head
  아래에 속하거나 활성 Weld/WeldConstraint로 Head에 직접 연결돼야 한다. SurfaceAppearance가 있거나 이름이
  중복·잘못 연결되면 적용하지 않는다.
- 원본 Head atlas/TextureID는 표정 atlas로 덮지 않는다. 열린 입이 파인 기존 머리의 수정본은 원본을 보존한
  별도 UV/메시 검증을 통과해야 한다. 실패한 atlas 파일은 업로드하지 않는다. ID/검증 메시가 부족하면 기존
  얼굴을 유지하고 `ExpressionReady=false`로 표시한다. 코스튬 OFF의 개인 Roblox 아바타 얼굴은 변경하지 않는다.
- 캐릭터 교체·죽음/퇴장과 몬스터 폴더 교체 때 이전 참조/연결을 정리한다. 비기본 표정만 만료 tick에 참여한다.
  남은 검증은 각 리그의 실제 얼굴 UV/원본 보존, 세 표정 전환, 이동·전투·대화 우선순위, OFF 얼굴 복귀다.
